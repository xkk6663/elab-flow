# 执行计划：串口通用发送面板（跨工程）

> 状态：**待评审**（2026-11-03）。本文件只定义改动边界与验收口径，不代表已实现。
> 相关文档：[技术迁移方案_串口监视与调试可视化.md](技术迁移方案_串口监视与调试可视化.md)、
> [技术方案_串口自定义发送组件.md](技术方案_串口自定义发送组件.md)（其「面板展示组件」部分由本计划收敛）。
> 工作规则见仓库 `AGENTS.md`：业务逻辑落 `services/elab/**` + `cockpit/server.py`，插件层只做展示与调用。

---

## 0. 一页纸结论

**目标**：做一个**跨工程通用**的串口发送面板，只保留三件事：

| # | 用户需求 | 现状 | 本轮动作 |
|---|---|---|---|
| 1 | 输入一串数字/字符 → **自动格式转换** | 必须手选 `utf8/ascii/gbk/hex` 下拉，无字节预览 | 新增「自动」识别（服务端判定）+ 实时字节预览；手动下拉可覆盖 |
| 2 | 输入框**记住前几次发送内容**，方便重发 | 已有 50 条、`↑/↓` 回填，但**只存文本**，不记格式/行尾 | 历史升级为 `{text, format, eol}`，回填时一并恢复；加历史下拉与去重 |
| 3 | **周期发送**一串信息 | 只有 per-project 组件能周期发，面板没有 | 新增「定时发送」：内核瞬态任务，可暂停/停止，不落盘 |

**同时收敛**（用户决定）：**面板不再展示 per-project 组件**。
`elab_serial_widget` 工具与 `/api/serial/widget*` 端点**保留**，作为 agent 按固定格式发送的能力；
`projects/<name>.widgets.json` 继续作为 agent 的命令库，不再占用面板空间。

**不做**：组件编辑 UI、每工程自动生成组件、多串口、周期运行中交错手发、任务跨重启恢复。

---

## 1. 范围

### 1.1 做

- 发送框：自动格式识别、服务端字节预览、历史增强、单次/定时发送、暂停/停止。
- 两个入口（驾驶舱宽栏 + DSH 窄栏）行为一致，阈值与编码全部由内核决定。
- 面板移除组件区（chips + 参数行 + 组件任务 UI），agent 能力不降级。
- 测试、文档、演示数据收尾。

### 1.2 不做

- 不做组件的新建/编辑界面（agent 仍可 `save/delete`）。
- 不做「每个工程自动带一个 raw 组件」。
- 不做周期任务运行中的交错手发（保持单任务独占串口）。
- 不做十进制字节输入（与文本数字冲突，见 §3.1）。
- 不做周期任务跨进程恢复（内存态，重启即失）。

## 2. 现状盘点（代码事实）

| 能力 | 驾驶舱 `cockpit/web` | DSH 插件 `packages/dsh-elab-cockpit` | 位置 |
|---|---|---|---|
| 格式下拉 | ✅ 4 种 | ✅ 4 种 | `SerialWorkspace.tsx` 发送表单 / `SerialPane.tsx` 发送表单 |
| 行尾下拉 | ✅ none/lf/cr/crlf/tab | ✅ 同 | 同上 |
| 发送历史 | ✅ 50 条、`↑/↓`、`localStorage` | ✅ 同一 key、同一逻辑 | `HISTORY_KEY = "elab.serial.send.history"` |
| 文件按行发送 | ✅ ≤ 2000 行 | ✅ 同 | — |
| 字节预览 | ❌ | ❌ | — |
| 周期发送 | ❌ | ❌ | — |
| per-project 组件 | ✅ 展示 | ✅ 展示 | 本轮下线 |

编码唯一入口：`services/elab/serialterm.py::build_payload()`（`SEND_FORMATS = ascii/utf8/gbk/hex`，`EOLS = none/lf/cr/crlf/tab`）。
历史只存 `string[]`，所以「回填一条 HEX 命令时若当前是文本格式」会按文本发出去——这是本轮要修的真实缺陷。

---

## 3. 设计决策

### D1 自动格式识别（保守判定）

服务端新增 `format="auto"`（不进 `SEND_FORMATS`，作为特殊值），由 `serialterm` 内部判定并返回**解析后的格式**。

判为 HEX 的**必要条件**（满足任一）：

1. 含 `0x` / `\x` 前缀；或
2. 含分隔符（空格 / 逗号 / 冒号）且每段为 1–2 位十六进制、总字节数为偶数。

其余一律按文本（默认 UTF-8；ASCII 可打印字符同样是 UTF-8）。行尾规则不变：文本沿用当前选择，HEX 强制 `none`。

| 输入 | 识别结果 | 理由 |
|---|---|---|
| `PING:42` | 文本 | 含非十六进制字符 |
| `0A FF` | HEX → `0A FF` | 分隔符 + 全十六进制 |
| `0x0A0xFF` | HEX | 有显式前缀 |
| `1234` | **文本** | 纯数字既可能是 `"1234"` 也可能是 2 字节，按文本更安全 |
| `你好` | 文本（UTF-8） | 非 HEX |
| `0A F` | 文本（并在预览处提示可手动切 HEX） | 字节数奇数/不完整，不猜 |

> 判定必须在**服务端**：预览与实际发送用同一份 `build_payload` 结果，避免“看的是 A、发的是 B”。
> 下拉仍保留 4 个显式格式；用户手选即退出自动模式（本次发送生效）。

### D2 服务端字节预览

`POST /api/serial` 增加可选 `dry_run: true`：

- 在 `_serial_blocker()` **之前**返回（预览不占口，闭环跑着也能先编辑）；
- 响应 `{ok, bytes, preview_b64, format, eol}`，**不写口、不写 journal、不进事件流**；
- 默认请求（无 `dry_run`）行为完全不变（C27：`POST /api/serial` 原语义不变）。

前端 150ms 防抖调用，显示 `将发送 N B · XX XX ..`；HEX 与文本都用同一条预览。

### D3 发送历史升级

- 结构：`{text, format, eol, at}`；读取时兼容旧的 `string[]`（迁移为 `format:"auto"`、`eol:"crlf"`）。
- 去重：`text+format+eol` 相同则移到末尾，不重复堆叠。
- 上限仍 50；跨工程、跨会话（浏览器本地），不做服务端存储。
- `↑/↓` 回填时**同时恢复格式与行尾**；另加一个历史下拉（现有点击触发），解决 `↑/↓` 的发现性问题。
- 两个面板使用同一 key 与同一结构（不同页面各自一份 localStorage，这是浏览器边界，不强行同步）。

### D4 周期发送 = 内核瞬态任务

- 新端点 `POST /api/serial/loop`：`{project, data, format, eol, interval_ms, count, dry_run}`。
- 复用 `serialwidgets` 的任务引擎：单一 `_JOB_LOCK`、固定节拍 + `skipped`、`pause/cancel`、`MAX_REPEAT_S`。
- **不落盘**：内存构造一个瞬态定义（`source:"raw"`），不读写 `projects/*.widgets.json`、不走 `rev`。
- 阈值：`MIN_REPEAT_MS = 20`；`count = 0` 表示直到手动停止；单任务最长 `MAX_REPEAT_S = 600s`。
- 进度轮询复用 `GET /api/serial/widget/job`，不新增 SSE topic。
- console 留档 `via:"raw-loop"` + `interval_ms`，便于事后复盘“这几百帧是哪来的”。

### D5 互斥与人的优先级

- 周期任务运行中：单次「发送」置灰，避免交错。
- 闭环 run 在跑：发送与定时发送都 409（N5 不变）；周期任务在跑时发起闭环/烧录同样被拒。
- 人点「停止/暂停」永远生效；agent 发起的周期任务不能阻止人操作。
- 周期任务**关面板不停**（与现有组件语义一致）→ 运行中必须有常驻徽标与停止按钮。

### D6 组件区下线，能力留给 agent

- 两个面板删除：组件 chips、参数表单、组件预览、组件任务进度/暂停/停止 UI。
- 保留：`/api/serial/widgets`、`/api/serial/widget/run|job|cancel|pause`、`elab_serial_widget` 工具、
  `projects/<name>.widgets.json` 格式与 `rev` 乐观锁、`allowAgentWrite` 门禁。
- `SERIAL_META` 的组件自描述保留（工具层与 agent 仍需要），面板不再消费。
- 不新增“是否显示组件”的开关：直接移除，恢复时从 git 历史取。

## 4. 里程碑与验收

### M1 通用发送（自动识别 + 预览）

**改动**：`serialterm` 增加 `resolve_payload()`（返回 `(payload, format, eol, error)`，`build_payload` 保留旧签名为薄封装）；
`POST /api/serial` 支持 `format:"auto"` 与 `dry_run`；两个面板加「自动」选项与预览行。

**验收**：

- `0A FF` 预览为 `0A FF` 且实发一致；`PING:42` 预览为 `50 49 4E 47 3A 34 32 0D 0A`（crlf）；
- 手选 HEX 后 `1234` 按 `12 34` 发出；手选文本后按 `"1234"` 发出；
- 闭环 run 在跑时预览仍可用（不 409），发送仍 409。

### M2 历史增强

**改动**：两个面板的历史读写与回填；结构迁移与去重；历史下拉。

**验收**：

- 发一条 HEX 命令 → 切到文本格式 → `↑` 回填 → 格式自动变回 HEX 且实发字节与首次一致；
- 连续重复发同一条 3 次，历史只留 1 条（在末尾）；
- 旧版本遗留的 `string[]` 能被读出，不丢历史。

### M3 定时发送

**改动**：`serialwidgets` 抽出 `start_job()` + 新增 `run_raw()`；`/api/serial/loop`；`SERIAL_META` 增
`raw_loop` 与 `loop` 限制段；插件 `routes.ts` 白名单、`icd.ts` 类型、`icd-client.ts` 方法；
`elab_serial` 增加 `repeat/interval_ms/count`；两个面板加「⏵ 定时」与运行态。

**验收**：

- F411 上 100ms 发 `PING:7` 跑 5s：轮次≈50、跳过=0、累计字节与轮次匹配；
- `interval_ms=10` 返回 400；`count=3` 跑完 3 轮自动 `done`；`count=0` 手动停止后 1s 内 `cancelled`；
- 周期运行中单次发送按钮置灰；发起烧录被拒（双向互斥）；
- 关掉面板任务继续跑，重新打开能看到进度（徽标不丢）。

### M4 组件区下线 + 文档收尾

**改动**：删除两个面板的组件 UI 与相关状态；更新插件 README、教程截图说明、技术方案 §4.7；
`f411.widgets.json` 是否精简（建议保留，作为 agent 的固定格式夹具；只删 `STATS/ECHO` 这类与
`PING` 同构的冗余项）。

**验收**：

- 面板不再出现「组件」行；串口页布局回收；
- agent 调 `elab_serial_widget list/run` 仍成功，`allowAgentWrite` 关闭时仍被拒；
- 无残留未使用的 import / 状态变量（tsc + lint 通过）。

## 6. 风险与回滚

| 风险 | 影响 | 对策 |
|---|---|---|
| `1234` 之类的输入被误判 | 发错字节，设备状态不明 | 保守规则（无分隔符/前缀一律文本）+ 预览可见 + 手动覆盖 |
| 周期任务关面板不停 | 用户以为已停，端口被持续占用 | 常驻运行徽标 + 停止按钮 + 600s 自动停 |
| 预览与实发不一致 | 调试结论错误 | 预览与发送共用 `resolve_payload`，前端不编码 |
| 两个面板实现漂移 | 两端行为不同 | 判定/阈值/文案全部由内核 meta 提供，面板只渲染 |
| 移除组件 UI 误伤 agent | 固定格式发送能力回退 | 保留全部端点与工具，只删渲染层；M4 验收显式检查工具可用 |
| `POST /api/serial` 语义变化 | 旧调用方受影响 | `dry_run` 为可选；无该字段时走原路径，C27 不变 |

**回滚**：M1–M3 每步独立可回滚；M4 只删前端渲染，回滚即从 git 恢复 UI 块，后端无迁移成本。
改完 `cockpit/server.py` 需同步两个检出（本仓 + 用户 elab 工作检出）。
