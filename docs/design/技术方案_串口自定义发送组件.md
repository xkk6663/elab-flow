## 0. 一页纸结论

**这一期不追求"再来一个面板"，而是把串口从"能看能发"补成"能连、能控、能解、能复现"。**

| # | 能力 | 分档 | 归属层 | 里程碑 |
|---|---|---|---|---|
| 1 | 串口线参数可配（数据位/校验/停止位/流控） | 必做 | 内核（serialport + config） | M1 |
| 2 | DTR/RTS 手动控制 + 硬复位 / 进下载模式 | 必做 | 内核（IO + 数据驱动预设） | M1 |
| 3 | 掉线检测 + 自动重连 + 连接态通知（含闭环前后自动让位/回归） | 必做 | 内核（serialmon + run 生命周期） | M2 |
| 4 | ESP-IDF 日志 / panic 结构化与符号化 | 必做 | 内核（通用引擎）+ 包内数据 | M6 |
| 5 | 自定义帧协议 profile + 实时解码预览 | 要做 | 内核（serialframes + codec）+ 面板 | M5 |
| 6 | 状态栏 RX/TX 速率 / 帧率 / 缓冲占用 | 要做 | 内核统计 + 两个面板 | M2 |
| 7 | 波形游标测量（Δt/ΔY）+ 每通道增益/轴 + 冻结快照 | 要做 | 前端（cockpit + 插件各一份） | M7 |
| 9 | 无硬件注入 + 虚拟信号源 | **不做**（已裁剪） | — | — |
| 10 | TCP client / server 与 UDP 传输 | 要做 | 内核（transport + netio） | M4 |

**明确不做**（本轮决策）：8 CSV 导出、9 无硬件注入/虚拟信号源、11 终端快捷键/本地回显、
12 命令面板入口；以及既有非目标：节点图/连线编排、脚本引擎、多串口并发、
浏览器侧本地生成数据。

**排序依据**：1/2/3 是所有后续能力的地基（IO 抽象、会话状态）；
10 依赖同一层抽象，先抽象后加传输；4/5 是"看得懂数据"的两条腿；
6/7 是纯展示层，可以最后做且不阻塞任何人。

**硬约束不破**：
- 工具层与内核之间只有 loopback HTTP ICD（[boundary.test.mjs](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/packages/dsh-elab-cockpit/test/boundary.test.mjs) 会拦）；
- 串口互斥 N5（`_serial_blocker`）语义不变；
- 监视输出不进 run 事件流（C17/C28），不落 console 留档；
- 芯片差异（复位时序、日志格式）只进 `packs/**` 的 `pack.yaml`，内核只做**通用解释器**；
- 步骤标签/三档定义只写 `cockpit/server.py` 的 `STEP_META` / `KERNEL_PLANS`。

**与旧文档的冲突裁定**：迁移方案 §0/§12 曾把「多传输（TCP/BLE）」列为不做。
本轮用户已决策要做 TCP client/server + UDP，本文**取代**该条非目标；BLE 仍不做。
迁移方案 §4.2「传输不动」仍然有效 —— 本方案不新增 SSE topic，一律走现有 HTTP 轮询。

### 1.2 数据面契约（二期必须继续遵守）

```text
读线程 read(4096)
  └─ _push_chunk(dir=rx)  →  chunks 环（seq / t_us / bytes 真值）
       ├─ _push_line()    →  lines 环（文本投影，seq 独立）
       ├─ _cap_emit()     →  capture JSONL（有界，5 MiB）

```

- 双游标：`seq`（行）与 `chunk_seq`（批）；`epoch` 只在**新会话**自增，前端据此清游标。
- gap 只报告不抹平（`covered` / `covered_chunks` / `dec_covered`）。
- 暂停只停"入环/展示"，读口继续（避免设备侧缓冲溢出）。

## 3. 总体设计

### 3.1 传输抽象（第 1/3/10 项的公共地基）

新增 [serialtransport.py](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/services/elab/serialtransport.py)：

```python
@dataclass(frozen=True)
class Target:
    kind: str          # serial | tcp-client | tcp-server | udp
    label: str         # 展示名：COM10 / tcp://192.168.1.5:9000
    port_spec: str     # 原始 spec（auto / COM10 / "://" URL），重连用
    baud: int
    line: LineConfig   # 仅 serial 有意义
    net: dict          # {host, port, bind, allow_remote}，仅网络传输
    reason: str        # 为什么选它（沿用 select_port 的诚实理由）
```

- `resolve(cfg, project, *, port="", baud=0, transport="", net=None)`：
  1. 读 `project.serial` → `host.serial` 默认值；显式参数优先；
  2. `transport` 缺省 `"serial"`；
  3. serial 复用 `sp.select_port`（USB 优先、排蓝牙、歧义报错）；
  4. 网络只做静态校验（host 非空、port 1..65535、非回环 bind 需 `allow_remote`）。
- `open(target, *, for_write=False)` → `SerialIO` / `NetIO`，并统一 `backend` 字符串。

**兼容**：`serialterm.resolve_target` 保留签名与返回键（`spec/port/baud/reason/backend/ports`），
内部改为调用 `serialtransport.resolve`，并**追加** `kind/line/net`。这样 `serialmon`、`monitor`、
`widgets` 不需要同时大改，只逐步替换。

|---|---|---|
| 线参数/传输/重连默认 | `projects/<name>.yaml` 的 `serial.*`；宿主默认 `elab.host.yaml: serial` | 是 |

### 3.3 ICD 总原则

- 所有写请求带 `actor`（内核注入，不由客户端自称）；agent 写操作仍受 `allowAgentWrite` 门禁。
- 所有"文件型"资源带 `rev`，不匹配返回 **409 + 最新内容**。
- 新增端点必须同步三处：`cockpit/server.py`、插件 `routes.ts` 白名单、`routes.test.mjs`。
- 出错必须"指名道姓"：缺后端 / 缺工具 / 不支持的传输，都要返回 `error` 与 `hint`，不静默降级。

## 4. 分项方案

### 4.1 第 1 项：串口线参数可配

#### 现状
- pyserial：`Serial(port, baud, timeout=0.2, write_timeout=wt)` —— 其余参数全默认。
- ctypes：`BuildCommDCBW("baud=... parity=N data=8 stop=1")` 写死。
- 配置只有 `port/baud`；快照只有 `port/baud`；UI 只有端口/波特率。

#### 数据模型

```python
@dataclass(frozen=True)
class LineConfig:
    data_bits: int = 8                 # 5|6|7|8
    parity: str = "none"               # none|even|odd|mark|space
    stop_bits: float = 1.0             # 1|1.5|2
    flow: str = "none"                 # none|rtscts|xonxoff|dsrdtr
```

校验（加载/请求时都跑，错误一次性列出）：
- `data_bits ∈ {5,6,7,8}`；
- `stop_bits=1.5` 仅允许 `data_bits=5`（Win32 DCB 限制），否则 400；
- `flow=dsrdtr` 需要 DTR/DSR 控制线，UI 提示"部分 USB 转串口不支持"；
- 未知键 → `warnings`（不静默吞掉拼写错误）。

映射：

| 字段 | pyserial | ctypes（`BuildCommDCBW` 串） |
|---|---|---|
| data_bits | `bytesize=` | `data={n}` |
| parity | `parity={'none':'N','even':'E','odd':'O','mark':'M','space':'S'}` | `parity={N/E/O/M/S}` |
| stop_bits | `stopbits=1/1.5/2` | `stop=1` / `stop=1.5` / `stop=2`（实测 `stop=15` 会被 `BuildCommDCBW` 拒绝） |
| flow=rtscts | `rtscts=True` | DCB flags：`fOutxCtsFlow=1` + `fRtsControl=HANDSHAKE` |
| flow=xonxoff | `xonxoff=True` | DCB flags：`fOutX=1` + `fInX=1` |
| flow=dsrdtr | `dsrdtr=True` | DCB flags：`fOutxDsrFlow=1` + `fDsrSensitivity=1` + `fDtrControl=HANDSHAKE` |

> 实现以「`BuildCommDCBW` 填基础串 + 手工补 flags 位域」为准（`_apply_dcb_flags`），
> 因为流控开关不在 `BuildCommDCB` 的字符串语法里。位偏移按 Win32 `DCB` 结构（flags DWORD @ offset 8）。

#### 文件级改动

### 4.2 第 2 项：DTR/RTS 控制 + 硬复位 / 进下载模式

2. **预设**：包内数据声明的时序，内核按表执行：

```yaml

        - { dtr: false, rts: true,  hold_ms: 100 }   # EN=LOW，进复位
        - { dtr: true,  rts: false, hold_ms: 100 }   # IO0=LOW
        - { dtr: false, rts: false, hold_ms: 50 }    # 释放，正常启动
```

  `for_write=True` 的句柄，执行完立即关。绝不新开第二个句柄去碰已占用的口。

### 4.3 第 3 项：掉线检测 + 自动重连 + 连接态通知

#### 现状（两个真缺陷）
1. **ctypes 读失败被吞**：[serialport.py L459-460](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/services/elab/serialport.py#L459-L461)
   `ReadFile` 返回 False 时直接 `return b""` —— 与"200ms 超时无数据"不可区分，
   USB 拔线后读线程会永远安静地空转。
2. **无重连**：[serialmon L188-197](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/services/elab/serialmon.py#L188-L197)
   异常 → 记录 → `alive=False` → 关口。UI 下一次轮询才发现会话没了。

#### 设计
**第一步：让掉线可见。**
- `serialport.py`：新增 `TransportLost(OSError)`；ctypes `read` 在 `ReadFile` False 时
  读 `GetLastError()`：
  - `ERROR_OPERATION_ABORTED(995)` / `ERROR_DEVICE_NOT_CONNECTED(1167)` /
    `ERROR_DEVICE_REMOVED(1617)` / `ERROR_ACCESS_DENIED(5)` → `TransportLost`；
  - 其它错误 → `OSError`（同样终止，但不触发重连）。
- pyserial：捕获 `serial.SerialException` 且消息含 `ClearCommError/device not configured/
  Access is denied/拒绝访问` → `TransportLost`。
- `NetIO` 的 `ConnectionResetError/BrokenPipeError` → `TransportLost`（供第 10 项复用）。

**第二步：会话内重连。**
- `_Session` 保存 `target`（`port_spec/baud/line/net/kind`）与：
  `reconnect {enabled, min_ms:200, max_ms:5000, max_attempts:0(∞)}`
  （来源：请求 > 项目 `serial.reconnect` > 默认 `enabled=true`）。
- 读线程重构成 `_pump()` + `_supervise()`：
  ```text
  try: _pump()                       # 现有循环体
  except TransportLost as e:
      if not reconnect.enabled: error/收摊
      else: 冲刷残留半行（不丢已有文本） → _reopen()
  ```
- `_reopen()`：`state="reconnecting"`；按 200→400→800→1600→3200→5000ms 退避；
  每次尝试 `serialtransport.resolve(原始 spec)` + `open`：
  - 原 `spec` 是显式 COM 且仍在 → 用它；
  - 原 `spec=auto` → 重新 `select_port`：唯一 USB 才用；多个候选 → **不猜**，
    继续等待并在 `reason` 里报歧义；
  - COM 号变化 → 记录 `port_changed:{from,to}`，`label` 同步更新。
- 成功：`state="live"`，`conn += 1`，`reconnects += 1`，更新 `backend`，
  清 `dec_pending`（断线前的半帧不可续），记录 `down_s`。
- **不 bump epoch**、**不清行/字节环**：这是同一逻辑会话，前端游标继续有效。
  UI 靠 `state/conn/reconnects/down_s` 显示横幅（横幅不是数据，不进环）。
- 失败耗尽 `max_attempts` 或租约到期 → `state="closed"`，`error` 如实。
- 重连期间 `write_through` 返回 `None`（UI 提示"正在重连，暂不可写"）。

1. `serialport.py`：`TransportLost` + ctypes 错误映射 + pyserial 异常归类。
2. `serialmon.py`：
   - `_Session` 增 `state/conn/reconnects/down_s/port_changed/last_error/target/reconnect`；

#### 4.3.6 闭环前后：端口让位与回归（用户点名要改的体验）

**现状（这是摩擦的根源）**：开着监视去跑闭环，会被**直接拒绝**：

```python
# cockpit/server.py L1653-L1661（原文）
if want_steps & _SERIAL_STEPS:
    mon = serialmon_mod.status()
    if mon.get("active"):
        return self._err(409, (
            f"串口监视正占用 {mon.get('port')}（project={mon.get('project')}）"
            f" —— 先在串口 Tab 点「关闭监视」再跑闭环（约束 N5）"))
```

于是实际流程变成"关监视 → 跑闭环 → 忘了再开 → 看不到日志"。这正是"闭环结束后串口是关的"的原因；
run 里的 `monitor` 步自己开一次口、收完即关，也不会替你留一个常驻会话。

**目标**：闭环结束后串口**持续打印**，且不需要人手动关/开。做法不是取消 N5，而是把"互斥"从
**报错**改成**让位 + 回归**：

```text
run 开始（steps 命中 flash/debug_verify/monitor）
  └─ 若监视会话在开：suspend()   —— 释放 IO，保留行/字节环，state="suspended"
       └─ run 正常用口（monitor 步仍走内核原生 monitor，不委托）
run 结束（ok / failed / cancelled / inconclusive）
  └─ resume()                    —— 用重连同一套 open 逻辑恢复；epoch 不变
       ├─ 原来有会话 → 恢复原 target（端口变了按 §4.3 的规则处理）
       └─ 原来没有会话 → 若 resume_after_run="open"，新开一个监视会话
```

实现要点：

1. `serialmon.py`
   - `suspend(reason)`：`io.close()`，`state="suspended"`，`suspend_reason`，**不清环、不 bump epoch**；
     读线程退出但会话对象保留（与 `closed` 区分，前端不清屏）。
   - `resume()`：按保存的 `target` 重开（复用 §4.3 的退避/不猜口规则）；失败则 `state="suspended"` +
     `resume_error`，由前端"重试"按钮或下一次轮询重试。
   - `suspended_by_run: bool`：只有"因 run 让位"的会话才允许自动恢复；人手动关掉的**不**恢复。
2. `server.py`（run 生命周期）
   - `/api/run` 的 409 分支改为 `serialmon_mod.suspend(reason=f"run {run_id} 需要串口")`，
     然后正常 `mgr.spawn`；`spawn` 抛错则立刻 `resume()`。
   - `RunManager._follow_loop` 的 `finally`（[server.py L427-L443](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/cockpit/server.py#L427-L443)，进程退出、
     `stream/closed` 扇出、登记簿摘除都在这里）新增 `on_finish(ar, rc)` 回调，在其中 `resume()`，
     用**引用计数**：只要还有活跃的 `_SERIAL_STEPS` run 就不恢复，最后一个结束才恢复。
   - 人手动关会话 → 清 `suspended_by_run`，终态不恢复。
   - `resume_after_run` 取值 `open`（默认）| `restore` | `off`，来自请求 > 项目 `serial.resume_after_run`。
3. 前端
   - 删掉"先在串口 Tab 点关闭监视"的提示路径；改为 toast："闭环占用串口，监视已暂停，结束后自动恢复"。
   - 会话横幅显示 `已暂停（闭环占用）` + 「立即恢复」（run 结束后才可用）。
   - 若 `resume` 失败：横幅 `恢复失败：端口被占用`，保留手动重试；不反复弹窗。

**验收**
1. 监视开着 → 直接点闭环（含 flash/monitor）→ 不再 409；监视横幅显示"已暂停（闭环占用）"。
2. run 结束 → 监视自动恢复，**日志从恢复点继续打印**；行/字节环未被清空，`epoch` 不变。
3. run 取消 / 失败 / `inconclusive` → 同样恢复（状态不影响回归）。
4. 人中途手动"关闭监视" → run 结束后**不**自动打开（尊重人的意图）。
5. 两个 serial 相关 run 并行（agent 场景）→ 等最后一个结束才恢复一次，不重复开。
6. `resume_after_run=off` → 回到旧行为（结束即关）。

**测试**
- 单测：`suspend/resume` 状态迁移、`suspended_by_run` 门控、引用计数、`spawn` 失败即恢复。
- 集成：开监视 → 跑 build-only（不让位）→ 监视不受影响；跑 monitor → 让位/恢复。
- 真机：ESP32 跑一次 flash+monitor，结束后串口继续出日志（肉眼 + `elab_serial_read` 双向确认）。

**风险**
- run 若**硬崩**（进程被杀）没走到终态回调 → 会话停在 `suspended`。缓解：run 心跳/终态兜底
  （轮询"没有活跃 serial run 且 `suspended_by_run`"→ 恢复），并允许手动「立即恢复」。
- 自动新开监视会让后续 CLI 直连串口时看到"被占用"；CLI 侧沿用现有 `_blocker` 提示即可
  （驾驶舱内下一次 run 已能自动让位，不受影响）。

### 4.5 第 5 项：自定义帧协议 profile + 实时解码预览

#### 数据模型（`projects/<name>.frames.json`，rev 乐观锁）

```json
{
  "version": 1,
  "profiles": [{
    "id": "vendor-x-status",
    "label": "厂商 X 状态帧",
    "kind": "binary",
    "frame": { "head_hex": "A5 5A", "tail_hex": "0D 0A", "length": null, "max_bytes": 256 },
    "checksum": { "kind": "crc16modbus", "at": "tail" },
    "fields": [
      { "name": "rpm",  "offset": 2, "type": "u16", "endian": "le", "scale": 0.1, "unit": "RPM" },
      { "name": "temp", "offset": 4, "type": "i16", "endian": "le", "scale": 0.01, "unit": "℃" },
      { "name": "mode", "offset": 6, "type": "u8",  "enum": { "0": "IDLE", "1": "RUN" } },
      { "name": "name", "offset": 7, "type": "ascii", "length": 8 },
      { "name": "raw",  "offset": 15, "type": "bytes", "length": 4 }
    ]
  }]
}
```

约束：
- `id` `[a-z0-9_-]{1,32}`，工程内唯一；最多 32 个 profile、64 个字段、单帧 ≤256B、文件 ≤64KiB。
- `type ∈ {u8,u16,u24,u32,i8,i16,i24,i32,f32,f64,ascii,bytes}`；`endian ∈ {le,be}`；
  `scale` 默认 1、`bias` 默认 0；`enum` 仅对整型。
- `frame` 至少给 `head_hex` 或 `length`；`tail_hex` 可选；三者都给时以"头 + 长度"切帧，
  尾标记只做校验。
- `checksum ∈ {none,sum8,xor8,crc16modbus}`；失败帧计入 `skipped` 并保留原因（不静默丢）。
- 数值字段默认 `plot:true` → 成为波形通道；`bytes/ascii` 只出现在字段表。

  - `decoder="profile"` 时用 `profile` 字典；新增返回：
    `records: [{fields:{...}, values:[...]}]`、`fields: [{name,unit,plot}]`、
    `checksum_fail`、`pending_b64`（沿用现有语义）。

  - CRC16-Modbus 是通用算法，放内核；不引入第三方依赖。
- 会话：`decoder` 允许 `"profile:<id>"`；`set_decoder(cfg, project, ...)` 需要工程上下文，

   `measure(lo,hi,i,j)`、`autoRange(values)`（可单测，避免把数学埋进 canvas）。
2. `SerialWorkspace.tsx`：
   - 视图状态 `chanView`、`cursor`、`freeze`；
   - `WaveChart` props 增加 `chanView/cursor/onCursor/onAutoRange`；
   - 监听：`onPointerDown`（游标）、`onWheel`（现有缩放）、拖拽（平移）；
   - 解码源切到 `stream.decoded`（会话开）并保留 fallback。
3. `SerialPane.tsx`：镜像同一套交互（代码不共享，数学模块两边各放一份**同测试向量**）。
4. `services/elab/serialcodec.py`（可选）：无状态解码返回每帧 `index`，用于 Δ帧（无 t_us 时的最小信息）。

#### 验收
1. 板端 100 Hz 三通道正弦 → 选两点：`Δ帧=10` 时 `Δt≈100ms`（±5%）；无板时用内核 `loop://` 自测。
2. 通道 2 设 `gain=0.5`、`offset=0` → 幅度减半；`offset=100` → 整条上移（自动量程下也可见）。
3. 冻结后板子继续输出：曲线不动、帧计数停；解冻立即追到最新。
4. 无会话（离线解码）时：游标可用、ΔY 可用、Δt 显示 `—`。

#### 测试
- 单测（新 `waveMath.ts`）：坐标映射、最近点吸附、Δ 计算、自动量程（空/单点/常量数组）。
- 手工（无 canvas 测试框架）：两面板同操作同结果；高 DPI 下坐标正确。

#### 风险
- 两套前端重复实现 → 漂移。缓解：数学抽纯函数 + 同一测试向量；canvas 交互只做薄壳。
- 大数据量下每帧重算量程 → 只在「自动量程」触发，不每帧重算。
- t_us 是**批次级**（`_decode_locked` 用 chunk 的 t_us），同一批内多帧时间相同 →
  Δt 精度受批大小限制。UI 标注"批次时间精度"；不要声称微秒级精确。

### 4.8 第 10 项：TCP client / server 与 UDP 传输

#### 现状
- pyserial `socket://host:port` 只在 `"://"` 分支被隐式支持，无 UI、无 TCP server、无 UDP。
- `monitor`/`serialterm`/`serialmon` 全部按"串口"写死解析与错误文案。

#### 设计
新增 `services/elab/netio.py`：

| kind | 打开 | 读 | 写 | 断链 |
|---|---|---|---|---|
| `tcp-client` | `create_connection((host,port), 3s)`，之后 `settimeout(0.2)` | `recv(n)`；超时返回 `b""` | `sendall`（2s 超时） | `ConnectionResetError/BrokenPipe` → `TransportLost` |
| `tcp-server` | `bind + listen(1)`；`accept` 在 0.2s 超时内轮询 | 未连：`b""`；已连：`recv` | 无客户端返回 0 | 客户端断开 → `TransportLost`（回到监听态，不关会话） |
| `udp` | `bind((host,port))` | 一条数据报（截断到 n） | `sendto` 最近对端 | 无（UDP 无连接） |

- 统一实现 `read/write/close/backend`，并 `state` 上报 `listening|connected`。
- **安全默认**：bind 地址默认 `127.0.0.1`；非回环地址必须 `elab.host.yaml:
  serial.net.allow_remote: true`；UI 首次启用弹警告（驾驶舱无鉴权，等于把调试口暴露到局域网）。
- tcp-server 的 `read` 在监听期返回 `b""`，但 `state="listening"` 让 UI 显示"等待客户端连接"。

#### 配置
```yaml
serial:
  transport: tcp-client        # serial | tcp-client | tcp-server | udp | virtual
  net: { host: 192.168.1.50, port: 9000, bind: 127.0.0.1 }
```
- `serial.port` 仍用于串口；网络时作为展示标签（可留空）。
- 兼容：不写 `transport` = `serial`，行为不变；`port` 里写 `socket://...` 仍走 pyserial URL（保留，标注"老写法"）。

#### 文件级改动
1. `netio.py`（新）。
2. `serialtransport.py`：`resolve` 支持 transport/net；`open` 分派。
3. `serialterm.py`：`resolve_target` 透传 `kind/net`；`_roundtrip` 走 `serialtransport.open`。
4. `serialmon.py`：`open_session(..., transport, net, virtual)`；快照 `kind / label / net / state`；
   错误文案按 kind 分支（"端口" vs "连接"）。
5. `monitor.py`：改用 `serialtransport`；`on_open` 记录 `kind`；网络传输下 `serial_port` 为标签。
6. `server.py`：
   - `POST /api/serial/monitor open` 接受 `transport/net/virtual`；
   - `POST /api/serial` 发送接受同样字段；
   - `SERIAL_META.transports = ["serial","tcp-client","tcp-server","udp","virtual"]` +
     `net_defaults`；
   - `features += ["net_transport","udp"]`。
7. `routes.ts` 无新路径（复用 `/api/serial*`），但白名单/测试要覆盖 body 字段（`routes.test.mjs`）。
8. `EvidenceRail.tsx` / `SerialPane.tsx`：连接行加"连接方式"选择；网络时显示 host/port，
   隐藏波特率/线参数/DTR-RTS；会话标签显示 `tcp://host:port`。

#### ICD 示例
```http
POST /api/serial/monitor
{ "action":"open", "project":"esp32s31_korvo",
  "transport":"tcp-client", "net":{"host":"192.168.1.50","port":9000},
  "reconnect":{"enabled":true} }
→ { "ok":true, "kind":"tcp-client", "label":"tcp://192.168.1.50:9000",
    "state":"live", "baud":0, "line":null }
```

#### 验收
1. 本地 `socketserver` echo（`127.0.0.1:9100`）→ tcp-client 打开，`POST /api/serial` 发送，
   回显出现在 RX 字节面。
2. tcp-server 绑定 `127.0.0.1:9200`，`nc` 连入 → `state:listening → connected`，双向数据。
3. UDP：本机发包 → 字节面出现一条数据报；发送 → `sendto` 最近对端。
4. 网络断链 → 第 3 项重连接管（`state=reconnecting`）。
5. 非回环 bind 未开 `allow_remote` → 400 + 明确提示。

#### 测试
- 单测：`NetIO` 三种子在临时端口上的读写/断链（线程 + `socketserver`）。
- 单测：`resolve` 校验（端口越界、空 host、非回环未授权）。
- 集成：monitor 走 tcp-client 拿数据；DTR/RTS 返回不支持。

#### 风险
- **暴露面**：tcp-server/UDP 会让本机成为入口 → 默认回环 + 显式开关 + 警告；
  文档写明"驾驶舱无鉴权，勿绑 0.0.0.0"。
- UDP 无连接语义 → 不做"掉线重连"，只统计收发。
- 网络延迟下 `write` 超时与串口语义不同 → 统一 2s，超时如实报错。

## 5. 里程碑与依赖

> 只给顺序与出口条件，不给工期。

```text
M1 连接层地基（1/2 + 抽象）
 ├─ serialtransport + LineConfig + SerialIO.set_control + ctypes 错误映射
 ├─ 配置/快照/自描述/面板连接设置
 └─ 出口：7E1 能开；DTR/RTS 与 ESP32 复位预设可用；旧行为零回归

M2 会话韧性（3/6）
 ├─ TransportLost + 重连状态机 + 状态栏统计
 ├─ 闭环让位/回归（suspend/resume，§4.3.6）
 ├─ 出口：拔插自动续流；闭环结束后日志继续打印；100 Hz 真实流 fps 正确
 │
 ├── M4 网络（10）          ← 依赖 M1 抽象 + M2 重连
 ├── M5 帧 profile（5）     ← 依赖 M2（会话解码/统计）
 ├── M6 日志/panic（4）     ← 依赖 M5 的会话属性模式（可并行）
 └── M7 波形（7）           ← 依赖 M5 的 t_us/共享解码（最后做）
```

**为什么这么排**
- M1 不先做，后面每个功能都要各自解析端口/参数，会产生 4 套分叉；
- M2 的重连/统计/让位回归都改会话与快照，一次改完两个面板同时受益；
- M4 是"换一种 IO"，必须站在 M1 抽象上；
- M5 的 profile 是 M6（字段/记录）与 M7（t_us）的前置；
- M7 纯前端且要改两份，放最后避免被前面反复返工。

## 7. 风险与回退

| 风险 | 影响 | 缓解 / 回退 |
|---|---|---|---|
| 网络传输暴露 | 本机调试口被局域网访问 | 默认 `127.0.0.1`；`allow_remote` 显式开启；UI 警告；不做零配置 0.0.0.0 |
| 两套波形漂移 | cockpit 与插件行为不一致 | `waveMath.ts` 纯函数 + 同一测试向量；canvas 薄壳 |
| 板级 DTR/RTS 接线差异 | 复位预设"没反应" | 预设是包数据；UI 显示实际值并注明取决于硬件；原始开关始终可用 |
| ctypes 能力差异 | 1.5 停止位/流控/线路控制不生效 | 能力探测写进 `capabilities`；不支持就明确报错，不假装 |
| 重连抢口/COM 变号 | 串到别的设备 | 显式 spec 优先；auto 多候选不猜；`port_changed` 可见 |
| 让位后没回归（run 硬崩） | 监视停在 `suspended` | 终态回调 + 心跳兜底 + 手动「立即恢复」；`resume_after_run=off` 可回退 |
| 包缺新字段 | 老包/第三方包打开报错 | 全部可选：缺省 8N1、无预设、无日志 profile |
| 1 MiB 环 + 高频统计 | 读线程卡顿 | 限长 deque + O(1) 摊销；超限标 `warmup` |
| 双检出不同步 | 面板调新端点 404 | 改 `server.py` 的清单写入发布流程；CI 检查 |
| 旧客户端不带新字段 | 行为变化 | 服务端全默认；`SERIAL_META` 只加不改 |

**回退开关**（出问题不改代码就能关）：
- `serial.reconnect.enabled=false`
- `serial.transport` 不写 = serial
- `serial.line` 不写 = 8N1
- 不选 profile / 不选 log profile = 零新逻辑
- `serial.resume_after_run=off` = 闭环结束后不自动恢复监视
