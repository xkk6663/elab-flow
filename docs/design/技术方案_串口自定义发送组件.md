# 技术方案：串口「自定义发送组件」（参数化命令积木）

> 状态：**M1 / M2 / M3 已实现并真机验收**（2026-11-02，F411/COM10）：数据模型 + 服务端渲染/校验 + 单条发送 + 驾驶舱组件行；
> M2（序列 `send/delay/wait`、周期发送固定节拍 + `skipped`、暂停/恢复/停止、400ms 轮询）；
> M3（DSH `SerialPane` 窄栏组件 UI、`elab_serial_widget` Agent 工具 + `allowAgentWrite` 门禁 + `rev` 乐观锁）。
> 真机结论：`ping_ack` 命中 `PONG:`；关回显后 `wait` 超时整轮 `failed`；`ping_loop` 暂停后轮次冻结、恢复后 `skipped` 增加、停止后 `cancelled`。
> 调研对象：[Lissio](https://codeberg.org/Horldsence/Lissio) `lissio-industries/Lissio`（默认分支 `develop`，Apache-2.0）。
> 本仓现状基线：`services/elab/serialmon.py`（字节面 / 共享解码）、`services/elab/serialterm.py`（发送载荷）、
> `cockpit/web/src/serial/SerialWorkspace.tsx`（四视图 + 发送面板）、`docs/design/技术迁移方案_串口监视与调试可视化.md`（P1–P3.5 已完成）。

---

## 0. 一页纸结论

**要做的不是"再做一个发送框"，而是把"一次调试命令"变成可命名、可参数化、可复用的组件。**

| 结论 | 内容 |
|---|---|
| 组件形态 | **模板 + 类型化参数 + 可选多步**（send / delay / wait），不是 Lissio 的 React Flow 节点图 |
| 存储 | 工程级 `projects/<name>.widgets.json`（与 `adapt` 生成的 `<name>.yaml` 解耦，可提交、可共享） |
| 唯一事实源 | 渲染与校验**只在服务端**（`serialwidgets.py`）；面板与 agent 都调同一个 `dry_run` 拿字节预览 |
| 复用现有出口 | 每个 send 步仍走 `serialterm.build_payload()` + `serialmon.write_through()`，不新增写口路径 |
| 传输 | **不新增 SSE topic**；序列任务用 HTTP 轮询拿进度（沿用方案 §4.2「传输不动」） |
| 硬约束 | N5 互斥、C17（不写事件流）、C27（写通道语义不变）、C28（留档独立）、allowAgentWrite |
| 与 Lissio 的差异 | Lissio 有"参数化模板 + 定时触发"，但**没有多步延时/序列**；我们做线性序列即可覆盖，且更适配窄栏 |

优先级建议：**M1 单条参数化组件（P0）→ M2 参数表单 + 序列 + 周期发送 → M3 Agent 全权（增删组件 / 运行 / 暂停）+ 证据快照**。

## 1. 需求拆解

用户原话："可以自己做数据流，然后点击新增的组件按钮进行串口发送；还可以设定参数，发送参数方便参数调试。"

拆成四条可验收的需求：

| # | 需求 | 验收口径 |
|---|---|---|
| W1 | **自制数据流**：用户能定义要发的字节/文本（含 HEX 帧），而不是每次手敲 | 定义一次，反复点按钮发；预览字节与服务端实发一致 |
| W2 | **组件按钮**：定义好的组件以按钮/chip 形式出现在串口工作区，点一下就发 | 宽栏（驾驶舱）与窄栏（DSH）都能看到并触发 |
| W3 | **参数调试**：组件接受参数（PID 三个浮点、模式枚举、地址 HEX…），改参数不用改模板 | 每个参数有类型/范围/默认值；越界在发之前被拒 |
| W4 | **可复盘**：发过什么参数、结果如何能回看 | TX 进字节面 + console 留档带参数快照 + 每步结果 |

明确**不做**（与仓库既有非目标一致）：节点图/连线编排、脚本引擎、多串口并发、二进制协议 profile 系统。

## 2. 现状盘点（已经有什么，缺什么）

### 2.1 发送链路（可直接复用）

```text
SerialWorkspace 发送面板
  └─ POST /api/serial {data, format, eol, encoding, project}
       ├─ serialterm.build_payload()        ← 文本/ASCII/UTF-8/GBK/HEX + 行尾，唯一编码入口
       ├─ _serial_blocker(mgr)              ← 有 run 在跑 → 409（N5）
       ├─ serialmon.write_through(payload)  ← 监视会话开着 → 同口写穿，TX 入数据面
       └─ serialconsole.journal_for(...)    ← TX 留档（"我敲过这一行"）
```

- 发送格式：`utf8 / ascii / gbk / hex`；行尾：`none / lf / cr / crlf / tab`
- 发送历史：`localStorage` 50 条，↑/↓ 回填；文件按行发送上限 2000 行
- HEX 模式**不追加行尾**（二进制帧多一字节就是错）
- TX 与 RX 同构进同一份字节面（方向过滤 `all/rx/tx` 可看）

### 2.2 缺口

| 缺口 | 现状 | 后果 |
|---|---|---|
| 命令不可命名/不可复用 | 每次手敲或从历史回填 | 同一组调试命令反复敲，易错 |
| 没有参数概念 | 模板就是最终字符串 | 调 PID 要手动改数字，无法校验范围 |
| 没有多步 | 一次只能发一条 | "发命令 → 等 OK → 发下一条"只能靠 agent 的 `elab_serial_wait` |
| 没有周期发送 | — | 心跳/轮询只能手点 |
| 参数不留痕 | console 只记最终字节 | 复盘时不知道当时 Kp 是多少 |

## 3. Lissio 横向对比（本轮核对源码）

### 3.1 发送 / 自定义命令

| 能力 | Lissio | 证据 | elab 现状 |
|---|---|---|---|
| 参数化命令模板 | ✅ Profile 用 frame/message + operation 定义请求；字段 `number/string/bytes(HEX)/bool`，支持嵌套 JSON | `Lissio-Client/src/components/displays/command/CommandSender.tsx`、`profiles/FrameBlockEditor.tsx` | ❌ 无 |
| 参数注入 | ✅ 标量字段可绑定 F32 图输入口，图值覆盖表单常量 | `CommandOperationFields.tsx`、`lib/commands/profileCommands.ts` | ❌ 无 |
| 发送触发方式 | ✅ 每条命令 `manual / onChange / timer`（最小 10ms，后端 20ms tick） | `CommandSenderSidebar.tsx`、`Lissio-Server/.../runtime/command_sender.rs` | 仅手动 |
| 多条命令组织 | ⚠️ 预设标签页，**不是队列**，**无 delay/sequence** | `ProfileOperationsTab.tsx` | — |
| 发送历史 | ⚠️ RawData 仅最近 20 条回填 | `useSendHistory.ts` | ✅ 50 条（更强） |
| 文件发送 | ✅ 4KB 分块、进度/取消、64MiB，ASCII/UTF8/GBK/HEX | `useRawDataFileSend.ts` | ✅ 按行、上限 2000 行（够用，弱于分块） |
| 宏 / 脚本 | ❌ 无 | — | ❌ 无 |

**结论**：Lissio 的"参数化模板"来自它的 protocol profile 体系（帧定义 + operation）；我们不做 profile，
所以组件应**更轻**：模板字符串 + 类型化参数，不引入帧元数据。

### 3.2 数据流编排

| 能力 | Lissio | elab |
|---|---|---|
| 图编排 | ✅ React Flow + 后端 HIR 编译、环检测；节点含 Command / TextOut / Trigger / Math / FFT 等 | ❌（既有"不做"清单） |
| 连线语义 | ✅ points/bytes/f32/freq/string 同域才可连，跨 tab 拒绝 | — |
| 发送编排 | ⚠️ Command 经 `loopbackOut` 字节边 → Device.tx；**无 Sequencer/Delay** | ❌ |
| 条件触发 | ✅ Trigger 按文本规则输出 number/string，可驱动 TextOut | ❌（仅闭环 monitor 判据） |

**结论**：Lissio 的图解决的是**数据管道**（解码 → 运算 → 触发 → 输出）；我们要解决的是
**调试命令的复用**，线性步骤模型足够，且窄栏放得下。**不引入 React Flow**（与既有非目标一致）。

### 3.3 其它串口体验

| 能力 | Lissio | 证据 | elab 现状 |
|---|---|---|---|
| 多传输 | ✅ Serial / TCP client+server / UDP / SLCAN / CandleLight / Modbus / S7；设备树多节点并存 | `README.md`、`device-abstraction.md` | ❌ 单口（N5） |

| 记录 | ✅ DuckDB + 分页查询 + 只读 SQL + CSV/JSON，**无回放** | `Lissio-Data/.../recording` | ✅ 有界 JSONL + **有回放**（更强） |

## 4. 自定义发送组件设计

### 4.1 概念与命名

一个 **SendWidget（发送组件）** = 名称 + 参数定义 + 一串**步骤**。点按钮 → 校验参数 → 渲染字节 → 按步骤执行。

```text
┌ 设置 PID ────────────────────────────────┐
│ Kp [1.00]  Ki [0.10]  Kd [0.00]          │   ← 参数（类型化、有范围）
│ 预览 21 B:  "pid 1.00 0.10 0.00\r\n"     │   ← 服务端 dry_run 的结果
│ [发送]  [循环 100ms]  [编辑] [删除]      │
└──────────────────────────────────────────┘
```

### 4.2 数据模型

存储文件：`projects/<name>.widgets.json`（UTF-8、原子写、可提交进 git）。

```json
{
  "version": 1,
  "widgets": [
    {
      "id": "pid-set",
      "label": "设置 PID",
      "group": "参数调试",
      "confirm": false,
      "format": "utf8",
      "eol": "crlf",
      "params": [
        { "name": "kp", "label": "Kp", "type": "float", "default": 1.0,
          "min": 0, "max": 20, "step": 0.01, "decimals": 2 },
        { "name": "ki", "label": "Ki", "type": "float", "default": 0.1,
          "min": 0, "max": 5, "step": 0.01, "decimals": 2 },
        { "name": "kd", "label": "Kd", "type": "float", "default": 0.0,
          "min": 0, "max": 5, "step": 0.01, "decimals": 2 }
      ],
      "steps": [
        { "kind": "send", "text": "pid {{kp}} {{ki}} {{kd}}" },
        { "kind": "wait", "within_s": 1.0, "match": { "kind": "regex", "pattern": "^OK" } }
      ],
      "repeat": { "interval_ms": 100, "count": 0 }
    },
    {
      "id": "read-ver",
      "label": "读版本",
      "format": "hex",
      "steps": [
        { "kind": "send", "text": "A5 5A {{addr}} 01" },
        { "kind": "delay", "ms": 20 }
      ],
      "params": [
        { "name": "addr", "label": "地址", "type": "hex", "default": "01",
          "width": 1, "endian": "be" }
      ]
    }
  ]
}
```

字段约束：

| 字段 | 约束 |
|---|---|
| `id` | `[a-z0-9_-]{1,32}`，工程内唯一 |
| `label` | ≤ 24 字；chips 上显示 |
| `steps` | 1–20 条；`send` 必须至少一条 |
| `format` | `utf8 / ascii / gbk / hex`；步骤可覆盖 |
| `eol` | `none / lf / cr / crlf / tab`；HEX 步骤强制 `none` |
| `repeat` | `interval_ms ≥ 20`；`count=0` 表示直到手动停止；**重复整个组件**，固定节拍不重叠 |
| `confirm` | `true` 时 UI 弹确认（agent 必须显式 `confirm=true`） |

### 4.3 参数系统

| 类型 | 输入 | 渲染规则 | 校验 |
|---|---|---|---|
| `int` | 整数 | 十进制；或 `render=hex` 时按 `width` 零填充 | `min/max/step` |
| `float` | 小数 | 固定 `decimals` 位（默认 3） | `min/max/step`；拒绝 NaN/Inf |
| `bool` | 开关 | `true_value` / `false_value`（默认 `1/0`） | — |
| `enum` | 下拉 | 选中项的 `send` 值 | 必须在 `options` 内 |
| `string` | 文本 | 原样；**禁止 CR/LF** | `max_len`、可选 `pattern` |
| `hex` | 十六进制 | `width*2` 个大写十六进制字符；`endian=le` 时按字节反序 | 必须是合法 hex；宽度必须匹配 |

渲染规则细节：

- 模板占位符 `{{name}}`；字面量 `{{` 用 `\{{` 转义。
- **数值进 HEX 模板必须显式声明** `render:"hex"` + `width`，否则 400 报错并指出字段 —— 防止"0x1F 被当十进制 1F"。
- 渲染完成后仍交给 `serialterm.build_payload()` 做最终编码 —— **不另写第二个编码器**。
- 未声明的占位符、未知参数、重复参数名 → 加载时即报 `warnings`，不静默忽略。

### 4.4 执行模型

| 模式 | 触发 | 端口要求 | 说明 |
|---|---|---|---|
| **单条发送** | 点组件按钮 | 无会话也可 | 走现有写穿 / 无状态往返（同发送面板） |
| **序列**（含 `wait`） | 点「发送」 | **必须先开监视会话** | `wait` 需要连续 RX；没会话直接 400 并提示 |
| **周期**（`repeat`） | 点「循环」 | 建议开会话 | **重复整个组件**（含 `wait` 也可）；手动「暂停/停止」结束 |
| 预览 | 改参数时防抖 150ms | 不需要 | 调 `dry_run=true`，只渲染不写口 |

序列执行规则：

- 同进程**同时只允许一个组件任务**（第二个返回 409），避免两串序列交错。
- 每步结果结构化返回：`{i, kind, ok, t_ms, bytes, error, matched}`。
- `wait` 复用 monitor 的规则语义（regex / 子串 / HEX 子串），超时即该步失败并终止后续步骤。
- 总时长上限 60s（周期任务除外，周期任务 10 分钟后自动停）；取消走后标志位，**不杀线程**。
- 有闭环 run 在跑 → 统一走 `_serial_blocker()` → 409（N5 不变）。

**「重复单位」= 整个组件**：每个节拍把组件全部步骤从头跑一遍。

```text
组件「设置 PID」= [发 pid 2.5 0.1 0.0] → [等 OK]，节拍 100ms

固定节拍（不重叠）：
  t=0    第1轮 发 → 等 OK（耗时 50ms）
  t=100  第2轮 发 → 等 OK
  t=200  第3轮 发 → 等 OK
若某轮耗时 > 100ms，则该节拍点跳过本轮，并计入 skipped（只报告、不排队）
```

- 只有一个 `send` 步的组件 = 纯定时发送（心跳帧），节拍就是 `interval_ms`；
- 带 `wait` 的组件 = 每轮"发命令 → 等应答"，实际节拍 ≥ 一轮耗时；
- 没有"只重复某一步"的模式（会增加一套用户要理解的规则，收益为零）。

### 4.5 存储与作用域

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 写进 `projects/<name>.yaml` 的 `serial.widgets:` | 与工程描述同文件 | UI 写 YAML 会丢注释/格式（标准库无 ruamel），且破坏 `adapt` 的确定性产物 | ❌ |
| `projects/<name>.widgets.json` | 原子写、可提交、与 adapt 解耦、人可读 | 多一个文件 | ✅ **采用** |
| 浏览器 `localStorage` | 零后端 | agent 与 DSH 面板读不到，不可共享 | ❌ |
| `.work/` 下 | 不污染工程 | `--clean` 会删，备份即丢 | ❌ |

- 读取时校验；坏文件不阻塞串口功能，只在组件区显示「配置有 N 处错误」。
- 保存为临时文件 + `os.replace()` 原子替换；单文件上限 64 KiB、组件上限 64 个。
- 文件带 `rev`（整数，每次成功保存 +1）：**所有写请求必须带 `rev`**，不匹配返回 409 + 最新内容。
  这是「agent 与人同时编辑」的防丢更新机制——人的修改不会被 agent 的旧副本覆盖。

### 4.6 HTTP ICD（需同步进 `routes.ts` 白名单与边界测试）

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| GET | `/api/serial/widgets?project=f411` | — | `{ok, project, rev, widgets, warnings}` |
| POST | `/api/serial/widgets` | `{action:"save"\|"delete", project, rev, widget?, id?, actor}` | `{ok, rev, widgets, warnings}`；`rev` 不匹配 → 409 |
| POST | `/api/serial/widget/run` | `{project, id, params, dry_run?, repeat?, confirm?}` | `{ok, job_id?, preview_b64, bytes, error?}` |
| GET | `/api/serial/widget/job?id=…` | — | `{state, steps[], total_bytes, params}` |
| POST | `/api/serial/widget/cancel` | `{id}` | `{ok}` |

- `dry_run` 返回 `preview_b64`（客户端展示"将发送的字节"）。
- `actor` 由内核按调用方注入（`human` / `agent`）；agent 写请求受人设置的开关约束（见 §4.9）。
  两个入口用同一个 `rev` 乐观锁，后写者必须重读。正在运行的组件不可删除（先 cancel）。
- 错误沿用现有信封：400 = 参数/模板不合法，409 = 有 run 或已有组件任务，200+`ok:false` = 执行了但写失败。
- **不新增 SSE topic**（C18/C24 风险面不碰）；进度靠 300–500ms 轮询。

### 4.7 前端交互

宽栏（`cockpit/web`）：

```text
[行 | 字节 | 终端 | 波形]                     [方向][表示][搜索][暂停][清空][导出]
──────────────────────────────────────────────────────────────────────────────
组件  ▸设置PID  ▸读版本  ▸启停  ＋新建
      └ 展开参数表单：[Kp 1.00][Ki 0.10][Kd 0.00]  预览 21B  [发送] [循环] [编辑]
──────────────────────────────────────────────────────────────────────────────
[格式][行尾] [输入一行并按回车…..........................] [发送] [文件]
```

- chip 点击展开参数行（同一时间只展开一个）；运行中 chip 高亮 + 「停止」。
- 结果行：`✓ 2/2 步 · 21 B · 1.4 s`，点开看每步耗时/匹配行。
- 「＋新建 / 编辑」→ 弹窗（M2 先用 JSON 编辑 + 实时校验 + 预览；M3 再做结构化表单）。
- 未选工程或 widgets 文件损坏：组件区显示提示，发送面板照常可用。

窄栏（DSH `SerialPane`）：

```text
组件 [设置PID ▾]   Kp[1.00] Ki[0.10]   ▶   ⏹
```

- 下拉选组件 → 参数两列排布 → ▶ 运行；不提供编辑器（编辑回驾驶舱或手改 JSON）。
- 参数默认值来自服务端，面板不缓存业务语义（`capabilities.meta.serial.widget`）。

### 4.8 Agent 工具

新增第 18 个工具 `elab_serial_widget`：

| 参数 | 说明 |
|---|---|
| `action` | `list` / `run` / `status` / `cancel` / `save` / `delete` |
| `project` | 工程名 |
| `id` | 组件 id（list 不需要） |
| `params` | 参数对象（run 时必填，缺省用默认值） |
| `dry_run` | 只预览不写口（默认 `false`） |
| `confirm` | 组件 `confirm=true` 时必须显式传 `true` |

- `save / delete / run` 属**写**（改工程文件或写硬件），受 `allowAgentWrite` 门禁；`list/status/cancel` 只读。
- agent 可**实时增删组件**（`save/delete`）：保存必须带 `rev`，被人抢先改过则 409 并要求重读，
  人的修改永远优先。
- 返回结构与面板同源（每步结果 + 实发字节），便于 agent 说"我发了 21B，第 2 步等到 OK"。

**面板功能 ↔ agent 覆盖**（"agent 能操控面板所有功能"的落点）：

| 面板功能 | agent 工具 | 说明 |
|---|---|---|
| 选工程 / 切工作区 | 所有工具的 `project` 参数 | 面板选中状态是 UI 本地态，agent 按参数定位，不抢人的视图 |
| 三档闭环 / 单步 / 取消 / 预览 / 日志 | `elab_build` / `elab_triple` / `elab_loop` / `elab_step` / `elab_cancel` / `elab_preview` / `elab_log` | 已有 |
| 适配 / 装包 / 启用包 | `elab_adapt` / `elab_pkg` | 已有 |
| 开/关监视、选端口/波特率、换解码器、暂停/清空 | `elab_serial_monitor` | 已有 |
| 发送任意字节 | `elab_serial` | 已有 |
| 读批次 / 等内容 / 解码 / 共享帧 / 录制 | `elab_serial_read` / `elab_serial_wait` / `elab_serial_decode` / `elab_serial_decoded` / `elab_serial_capture` | 已有 |
| 组件：列表 / 运行 / 状态 / 取消 / 新增 / 删除 | `elab_serial_widget` | 本方案新增 |
| 视图切换、缩放、主题、面板展开 | — | 纯展示偏好，不开放；面板**跟随** agent 的实质动作自动切页 |

### 4.9 约束与安全

| 约束 | 落地 |
|---|---|
| **N5** | 统一 `_serial_blocker()`；组件任务也视为"占用串口"，与闭环双向 409 |
| **C17** | 组件任务**不写** run 事件流，只写 console 留档 |
| **C27** | `POST /api/serial` 原语义不变；组件走新端点 |
| **C28** | console 记录新增 `via:"widget:<id>"` + `params` 快照（追加字段，不改变既有读法） |
| **C31** | 沿用 serialmon 单例/自愈/写穿；任务不持口，只借会话 |
| 参数注入 | 值域校验在服务端；`string` 禁 CR/LF；hex 严格解析；模板长度上限 4 KiB |
| **权限模型** | **人 > agent**：人的「停止 / 暂停 / 取消」对 agent 的任务始终生效；设置页可一键收回 agent 写权限（403）；agent 不能阻止人操作 |
| **人机并发编辑** | `rev` 乐观锁；人保存成功即 `rev+1`，agent 下次保存 409 → 重读再改，人的修改不会被覆盖 |
| **可见性** | agent 每次动作带 `actor=agent`；组件条显示「agent 执行中 · 组件名 · 参数 · 步骤进度」；面板可自动切到串口页跟随 agent（人手动切走后不再拽回） |
| 危险操作 | `confirm:true` 组件在 UI 弹窗、agent 需显式确认；写口失败不重试 |

### 4.10 为什么不做节点图

Lissio 的 React Flow 解决的是"数据管道"（解码 → 数学 → 触发 → 输出），依赖后端 HIR 编译与类型系统；
我们的需求是"把一条调试命令做成按钮"，线性步骤即可表达，且 DSH 右栏只有 ~360px。
引入节点图会同时撞上既有非目标、增加前端依赖、并让 agent 难以稳定调用 —— **明确不做**。

## 6. 里程碑与验收

### M1 —— 数据模型 + 渲染 + 单条发送（后端闭环）

- 新增 `services/elab/serialwidgets.py`：加载/校验/渲染/`dry_run`/单条执行/任务状态。
- `cockpit/server.py`：5 个端点 + `SERIAL_META.features` 增补 + `meta.serial.widget` 自描述。
- 宽栏 chips 行 + 参数默认值表单 + 预览 + 发送。
- 测试：`tests/test_serialwidgets.py` ≥ 18 例（渲染/越界/hex 宽度/转义/坏文件/限制/409）。

**验收**：手写一个 `pid-set` 组件 → 面板出现 chip → 改 Kp 为 2.5 → 预览字节与 `dry_run` 一致 →
点发送 → 字节视图出现 TX 批次 → console 记录含 `params`；关掉监视后仍可单条发送。

### M2 —— 参数表单 + 序列 + 周期发送 + 结果视图（已实现）

- `wait` / `delay` 步骤 + 任务轮询 + 取消 + 每步结果展开。
- **周期发送**：重复整个组件，固定节拍不重叠（上一轮未完则跳过并记 `skipped`）。
- 参数表单（类型化控件、范围提示、错误定位到字段）。
- 无监视会话时序列返回 400 并给出一句话指引。

**验收**：`pid-set` 两步（发送 + 等 `^OK`）在真机 F411 上跑通；把设备回显改成 `ERR` 时第 2 步失败且
第 3 步不执行；取消后 1s 内状态变 `cancelled`。

### M3 —— 窄栏 + Agent 全权 + 证据（已实现）

- DSH `SerialPane` 组件下拉 + 参数 + ▶；编辑仍回宽栏。
- `elab_serial_widget`（第 18 个 `elab_*` 工具，9 个 action：list / preview / run / status / cancel / pause / resume / save / delete）含 **save/delete**：agent 可实时增删组件；`allowAgentWrite` 门禁 + `rev` 乐观锁。
- 权限收口：设置页「agent 写权限」总开关；人的停止/暂停优先；组件条显示 agent 执行态与参数。
- 边界测试：`routes.ts` 白名单、`boundary.test.mjs` 可见面。

**验收**：周期发 100ms、跑 5s 停 → TX 批次数量与时长匹配；DSH 面板与驾驶舱看到同一组组件；
agent 在未授权时 `run/save` 被拒、授权后可跑并返回每步结果；agent 新增的组件在 1s 内出现在两个入口；
人点「停止」能即刻终止周期任务，被终止的任务状态为 `cancelled`。

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 参数注入导致误发 | 设备进入未知状态 | 类型/范围校验 + `confirm` + 单任务串行 + 预览字节 |
| 序列占用会话时间长 | 别人无法用串口 | 总时长上限、可取消、同一时刻仅一个任务 |
| JSON 被手改坏 | 组件区不可用 | 加载即校验并给出行号级 warnings；不阻塞发送面板 |
| 前后端渲染漂移 | "看的是 A，发的是 B" | 服务端唯一渲染；客户端只展示 `dry_run` 结果 |
| 新端点绕过 N5 | 与 run 抢串口 | 统一 `_serial_blocker()`；任务只借会话，不自行 open |
| 工具层写死业务词 | 违反 AGENTS.md 规则 1/4 | 参数类型/步骤种类/限制全部进 `capabilities.meta.serial` |

## 8. 已定决策

| # | 问题 | 结论 |
|---|---|---|
| 1 | 组件归属 | **工程级共享**：`projects/<name>.widgets.json`，随工程提交、可导入导出 |
| 2 | 序列是否强制开会话 | **强制**：含 `wait` 的序列必须先开监视；单条发送不受限 |
| 3 | agent 权限 | **全权但人更高**：可实时增删组件、运行/暂停/取消、开关监视、改解码器；人可随时停止并收回写权限；`rev` 乐观锁防止覆盖人的修改 |
| 4 | 定时重复单位 | **重复整个组件**；固定节拍不重叠；单步组件即纯定时发送 |
| 5 | 人看 agent 的刷新率 | **300ms 轮询**（不新增 SSE topic） |
| 6 | 抢占 | 人点「发送」时，若 agent 的周期任务在跑 → **先停周期任务再发**（规则③） |

仅剩一个实现细节待定：周期任务的 `skipped` 是否需要在结果行显式展示（建议显示，与字节面的 `gap` 纪律一致）。
