## 2. 这些实现有什么用

### 2.1 源码级单步（窄栏 gutter）

现在的调试只能停在 `main`、函数断点或地址断点，排查业务逻辑要人肉对反汇编。
补上源码视图后：

- **“停在出错那一行”**：断点从“函数级/地址级”升级到 `文件:行`，与 Cortex-Debug 的日常体验对齐；
- **单步有语义**：`步过 / 步入 / 步出` 已在工具栏，源码行高亮后每一步都能看懂“跳进哪个函数、回到哪一行”；
- **窄栏可用**：右侧栏只有 ~660 px 时，用 4 字符 gutter（行号 + 断点点）竖排显示 40 行，不做三栏；
- **给 Agent 可落点**：Agent 拿到 `file:line` 后能直接下源码断点，不再靠反汇编地址猜。

典型场景：HardFault 复盘、`if` 分支走错、结构体越界、状态机卡死。

### 2.2 多会话并排

这里的“多会话”指**两个不同的调试目标**（不同工程或不同板子），不是对同一颗芯片开两份 GDB：

- **双板联调**：网关 + 节点、主 MCU + 从 MCU，两边同时暂停/单步，对照寄存器与变量；
- **boot / app 两工程**：F411 双槽方案里 boot 与 app 是两个 ELF，过去只能“关一个开一个”，现场会丢；
- **同工程 A/B**：两块板烧不同版本，并排看同一断点的变量差异；
- **人机分工**：Agent 在自己工程上调，人在另一工程观察，互不抢焦点。

同一块板**不能**开两个会话（一个 SWD 目标只能被一个 GDB 附着），本计划会显式拒绝并给出错误码，而不是让第二个 openocd 随机失败。

### 2.3 寄存器组编辑

- **上下文注入/恢复**：跳过 CRC 校验、模拟函数入参、恢复被异常破坏的 `sp/lr`，批量改一组比逐行点快；
- **FPU 调试**：浮点算法/传感器数据场景要直接改写 `s0–s31`，现在 UI 只有 `core` 组；
- **一次审计**：整组应用只落一条审计（含 before/after/items），比 N 条逐行记录更容易复盘“谁一次改了 12 个寄存器”；
- **与写权限模型一致**：仍需人类会话 `allow_write` + `confirm=true`，Agent 会话默认拒绝。

## 5. 功能 A：源码级单步 + 窄栏 gutter

### 5.1 目标与验收

- 停在有调试信息的行时，源码页签能显示该文件、当前行高亮、自动滚到视野中央；
- 行号左侧 4 字符 gutter：点击设置/取消 `kind=source` 断点，禁用态灰点可见；
- `步过 / 步入 / 步出` 后行号与高亮跟着变（`stop_seq` 递增不拿旧画面）；
- 无源码/路径失效时降级到反汇编，并给出明确原因，不白屏。

### 5.2 内核改动

**A1 源码读取端点（新增）**

```
GET /api/debug/source?debug_session=<id>&file=<path>&start=1&count=120
→ { ok, file, start, end, total, lines:[{no,text}], mtime, truncated }
```

- `file` 允许绝对路径或相对 `plan.source_dir`；解析后 `Path.resolve()` 必须仍在 `source_dir` 下（防 `..`/符号链接逃逸），否则 `400 debug-bad-request`；
- 只读文本，单次最多 512 KB / 400 行；超限 `truncated=true`；
- 找不到 → `404 debug-source-unavailable` + hint「ELF 无调试信息或源码已移动」。

**A2 帧带全路径**

- [debugdata.stack](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/services/elab/debugdata.py#L33-L54) 增加 `fullname`（MI 的 `frame.fullname`）；
- 无 `fullname` 时，内核用 `plan.source_dir` 建一次文件名索引（限制 5000 个文件，跳过 build 目录），按 basename 唯一匹配；多个同名文件不猜，返回空。

**A3 源码断点**

- 新增端点语义沿用 `POST /api/debug/breakpoints`，`kind="source"`，`location="<相对 source_dir 的 POSIX 路径>:<line>"`；
- [debugsession.breakpoint_add](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/services/elab/debugsession.py#L906-L943) 对 `source` 做绝对化 + 引号转义（Windows 空格/反斜杠必须实测）；
- 若 GDB 引号仍失败，降级方案：`-data-disassemble -f <file> -l <line> -n 1 -- 0` 取地址，插入临时地址断点，但持久化仍保留 `kind=source`（重建后重新解析，不写死地址）；
- `rev` 乐观锁、`debug.json` 持久化、审计沿用现有逻辑。

**A4 运行到源码行**

- `POST /api/debug/control` 增加 `action="run_to_line"`，body 带 `file/line`；
- 实现复用 `run_to` 的临时断点 + continue + 删除，只是定位方式换成 `file:line`。

### 5.3 两端 UI

- 页签表新增 `['src', '源码']`（放在「内存」前）；仅当 `snap.stop.frame.file` 非空时显示；
- 渲染：行号右对齐 + gutter 圆点（实心=启用，空心=停用，灰=非当前文件）；当前行背景 + 左侧 2 px 强调条；
- 交互：点 gutter 切换断点（`allow_write` 或断点权限即可，**不需要**内存写权限）；点行号选中行；`运行到本行` 走 `run_to_line`；
- 自动行为：每次 `stop_seq` 变化重拉当前文件（有缓存则不重复请求）；切页签才首次拉取；
- 窄栏：单列 40 行、横向滚动；宽屏：60–80 行；
- 降级：`file` 为空 → 页签显示「当前停止点无源码信息（检查 `-g`/ELF）」。

### 5.4 测试

- 单测：`source` 路径逃逸被拒；`fullname` 解析；源码断点 location 归一化；`run_to_line` 参数校验；
- 实机：`stm32c8_test` 在 `freertos.c` 设行断点、单步步入/步出；删除/禁用断点后 `rev` 递增；
- 文档：04/05 教程各加「源码页签 / gutter 断点」截图。

## 6. 功能 B：多会话并排

### 6.1 定义与硬边界

- 一个调试会话 = 一个 `DebugSession` + 一个 openocd/gdb 进程 + 一个目标；
- **同一工程 / 同一探针** 第二条会话 → `409 debug-target-busy`（提示先关闭）；
- 最多 2 条（配置 `debug.max_sessions`，钳制 1–4）；超出 `409 debug-session-limit`；
- 与串口/闭环 run 的互斥保持**全局**：任一会话存在时，烧录/串口仍按现有规则让位或 409。

### 6.2 内核重构

`DebugManager`：

| 现状 | 改为 |
|---|---|
| `self._sess: DebugSession | None` | `self._sessions: dict[str, DebugSession]` |
| `self._allow_write: bool` | `self._allow_write: dict[str, bool]` |
| `require()` | `require(debug_session="")`：空则唯一会话；多会话时必须指定 |
| `snapshot()` | 返回 `{ sessions:[…摘要…], session: <默认 id>, stop_seq… }`，保留顶层 `session` 兼容旧前端 |
| `_emit(topic,data)` | 绑定会话：信封 `session` 取事件来源；新增 `_emit_for(session_id,…)` |
| lease 巡检 | 遍历所有会话；Agent 租约到期逐个 `close(resume=true)` |
| `open()` | 生成/返回 `session_id`（已有），登记字典；同工程/同探针拒绝 |
| `close()` | 按 `debug_session` 关闭；缺省且只有一条时兼容旧行为 |

### 6.3 ICD 与 SSE

- 所有调试端点接受 `debug_session` 查询/JSON 字段；**不复用**聊天 `sessionId`；
- `GET /api/debug/session` → 摘要列表（项目、状态、owner、`allow_write`、`stop_seq`、`open_seq`）；
- `GET /api/debug/events?debug_session=<id>`：只推该会话；不带参数时全量（兼容单会话）；
- 插件 host 路由把 `debug_session` 转发给内核（见 [routes.ts](file:///c:/Users/xiao1/Desktop/ELAB/dsh-elab-flow/packages/dsh-elab-cockpit/src/adapters/kernel-http/routes.ts#L319-L338)）；
- ICD 文档 [ICD_cockpit_events](../design/ICD_cockpit_events.md) 补信封 `session` 语义与过滤规则。

### 6.4 插件面板 UI

- 调试壳层（原 `DebugView` 顶层）改为：
  - **会话条**：`项目 · 状态点 · owner`，`＋` 新会话（选工程），每个会话一个 `×`；
  - **单个**：一个 `DebugSessionPane`；
  - **并排**：容器 ≥1000 px 且 ≥2 会话时自动两列（也提供手动「并排」开关）；每列独立页签，默认左栈右寄存器；
- `DebugSessionPane` 只接收 `debugSessionId`，所有请求/SSE 带 `debug_session`；不再自己 open/close；
- 窄栏（<1000 px）：会话条 + 单 pane，切换会话即换数据源（不做上下堆叠）；
- 写权限按会话显示：Agent 会话 pane 的值只读，人类会话可写；
- 关闭一个会话不影响另一个，`monitor reset run` 只作用于自己的目标。

### 6.5 Agent 工具

- `elab_debug_open` 返回值里已有会话 id，补进工具说明；
- 所有 `elab_debug_*` 增加可选 `debug_session`；省略时：唯一会话直接用，多会话报 `debug-session-required`；
- `elab_debug_status` 返回会话列表，便于 Agent 选择。

### 6.6 测试

- 单测：manager 两会话互不串事件；同工程拒绝；关闭只影响目标会话；lease 巡检逐个到期；
- 手工：两块板（F103 + F411）或两个工程，左/右各暂停单步，确认栈/寄存器/PC 不串；
- 串口/闭环：任一会话存在时行为与单会话一致（不回归）。

## 7. 功能 C：寄存器组编辑

### 7.1 现状缺口

- 后端已返回 `core` / `fpu` 两组，但两端 UI 只请求 `group=core`；
- 写白名单只到 `r0–r12/sp/lr/pc`，`s0–s31` 不可写；
- UI 的 `editable` 与内核白名单相反（`pc/lr` 后端允许、前端禁写）；
- 只能逐行写，没有“本组一次应用”。

### 7.2 内核改动

- **组发现**：UI 改请求 `group=all`；响应保持 `groups:[{name,label,regs}]`；
- **白名单扩展**：
  - 保留 `r0–r12 / sp`；
  - 增加 `s0–s31`（32 位）；`pc/lr/xpsr` 继续只读（与 UI 对齐，后端也拒绝）；
  - `d0–d15 / q0–q15` 暂不开放写，UI 显示只读并标注「64/128 位待 P3b」；
- **宽度模型**：`_register_width(name)` → 32 / 64 / 128；`write_register` 接受 1–8 位（32）或 16/32 位 HEX（仅在未来 d/q 开放时）；
- **批量写（新增）**：
  ```
  POST /api/debug/registers
  { debug_session, confirm:true,
    items:[{name,value}, …] }        // 最多 16 项
  → { ok, applied:[{name,before,after}], failed?:{name,code} }
  ```
  - 先整批校验（白名单/宽度/HEX），任何一项不合法则整批不写；
  - 写前读一次 `registers(group=all)`，逐项 `set $name=…`，写后再读一次；
  - 审计一条：`action=write, target=register-group, items, before/after`；
  - **无事务回滚**：中途 GDB 失败时返回已应用列表与失败项，UI 明确提示，不假装原子；
  - 仍需 `allow_write` + 人类会话 + `confirm=true`。

### 7.3 两端 UI

- 寄存器页顶部加组切换（`内核` / `FPU`；`all` 返回几组显示几组）；
- 行内编辑保持现有；新增本地草稿：修改过的行高亮 + 顶部「应用本组（N）」；
- 应用成功后按新 `stop_seq` 刷新；目标继续运行/换帧时草稿失效并提示；
- `pc/lr/xpsr` 只读（与内核一致）；`d/q` 只读并显示原因；
- 宽屏 aside 的寄存器速览只读，不参与组编辑（避免误触）。

### 7.4 测试

- 单测：白名单（拒绝 `pc/lr`、接受 `s0`）；宽度校验；批量中途失败返回 applied；
- 实机：F411（有 FPU）改 `s0` 并读回；F103（无 FPU）不显示 FPU 组；
- 审计：验证一条 group 写记录包含全部 items 与 before/after。

## 9. 风险与决策点

| 编号 | 风险/决策 | 处理 |
|---|---|---|
| D1 | Windows 路径引号/空格导致源码断点失败 | 先做 30 分钟 spike：`-break-insert "C:\a b\main.c:79"`；失败改 `file:line` 解析成地址 |
| D2 | 源码路径逃逸 | `resolve()` + `is_relative_to(source_dir)`，拒绝符号链接 |
| D3 | 同一探针开两会话 | 按 `plan.name` 拒绝；同探针错误码 `debug-port-hijacked` 透出，不自动重试 |
| D4 | FPU 组宽度 | P3 只开放 `s0–s31`；`d/q` 标只读，避免 64/128 位解析错误 |
| D5 | 窄栏并排不可读 | 并排阈值 1000 px；窄栏只做会话切换 |
| D6 | 旧前端兼容 | `snapshot` 顶层字段保持不变；`debug_session` 缺省走唯一会话 |
| D7 | 事件串台 | SSE 信封已有 `session`，client 再按 `debug_session` 双保险 |
| D8 | 后端白名单与 UI 相反 | 统一为 `r0–r12/sp` + `s*`；`pc/lr/xpsr` 前后端都只读（需要 pc 跳转时用 `run_to_line`） |

## 10. 实施顺序（按依赖）

1. **A-内核**：`source` 端点 + `fullname` + 路径安全 + 源码断点引号 spike；

## 12. 明确不做

- 同一目标的多 GDB 附着（物理上不成立，直接拒绝）；

- 跨探针序列号自动识别（由用户保证两块板用不同探针）；
- RTT/SWO/LIVE WATCH。
