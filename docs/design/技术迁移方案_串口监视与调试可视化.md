## 0. 一页纸结论

**要迁的是"语义与算法"，不是技术栈。** Lissio 是 Rust + Tauri + React 的桌面应用；
elab 是"零依赖 Python 内核 + 浏览器前端 + DSH 插件"的本地工具。直接移植 Rust
后端或 Tauri 外壳会同时破坏 N3（clone 即跑）与分层边界（§4.3）。真正值得搬的是
三样已被上游验证过的东西：

1. **字节数据平面契约**：把串口输出从"按行文本"升级为"**带方向、带时间、可寻址的
   字节批次**"，原文永远是字节，文本只是投影（§1.2 / §7）。
2. **RawData 视图算法**：HEX/ASCII/UTF8/GBK、字节网格/行/终端三种视图、TX/RX
   方向过滤、时间戳/偏移、搜索、虚拟列表、发送面板、ANSI 流式终端（§1.3）。
3. **Agent 工具范式**："先读现状 → 小步写 → 每步验证 → 不确定先问"，以及
   `get_raw_data` / `send_bytes` / `send_string` 这组结构化读写工具（§1.5）。

**落地分三期，每期都可独立验收：**

| 期 | 目标 | 用户可见结果 | Agent 可见结果 |
|---|---|---|---|
| **P1 看得见、发得出** | 内核字节面 + 面板字节视图 + 发送面板接通 | 串口 Tab 里能看到带 `TX/RX` 方向与时间戳的 HEX/ASCII 流；发送框真的发出去了 | `elab_serial` 能发 HEX / 指定行尾 |
| **P2 看得懂、问得动** | ANSI 终端视图 + Agent 读/等工具 | 彩色日志、`\r` 覆写、UTF-8/GBK 增量解码正常；可搜索/暂停/清空 | `elab_serial_read` / `elab_serial_wait` 返回结构化批次与 `gap` |
| **P3 解得开、留得住** | 协议解码 + 波形 + 录制导出 | 设备按 JustFloat/FireWater 输出时直接出通道波形 | `elab_serial_decode` / `elab_serial_capture` 可断言数值、导出证据 |

> **2026-10-31 评审确认**：P1/P2/P3 全部纳入本期，按 P1 → P2 → P3 顺序实现与验收
> （决策见 §13）。

**不做**（§12）：Rust/Tauri/DuckDB、React Flow 节点图、多传输（TCP/BLE）、把串口输出
写进 run 事件流、改动 N5。

## 1. Lissio 调研结论

### 1.1 形态与出口

Lissio 是"伞仓库 + 5 个子模块"（`Lissio-Core/Data/Physical/Server/Client`），对外有
**四个出口**：Tauri 桌面、Web、MCP Server、CLI；前端与服务端之间是 **HTTP-RPC +
WebSocket 流式事件**，桌面壳只负责承载。这个形态与 elab 的"内核 HTTP + SSE + 浏览器"
高度同构 —— 差别在传输细节（WS vs 轮询），**不在能力语义**。故迁移面应限定在：

- 服务端：数据平面契约、环形缓冲、协议解码、RPC 语义；
- 客户端：视图状态机与渲染算法；
- Agent：工具描述与安全边界。

### 1.2 数据平面（最关键的一张契约）

`Lissio-Core/crates/shared/flow/src/lib.rs` 定义了全链路的 `FlowEnvelope<T>`：

| 字段 | 语义 | 对 elab 的启示 |
|---|---|---|
| `source_id` | 数据源（哪个口/哪条传输） | elab 只有单口单例，可退化为 `port` |
| `connection_epoch` | **连接纪元**：每次重连自增 | ★ elab 缺这个 —— 重开监视后 `seq` 归零，旧游标会静默看不到新数据 |
| `first_sequence` / `last_sequence` | 本批覆盖的序号区间 | 支持"按序号寻址 + 缺口检测" |
| `observed_time_unix_ns` | 采集时刻 | elab 只有 `HH:MM:SS` 文本，无法做时间轴/波形 |
| `direction` | RX / TX | ★ elab 目前**只有 RX**，TX 不进入数据面 |
| `gap_before` | 本批之前丢了多少 | 与 elab 的 `gap` 同义，做法已验证 |
| `payload` | `BytesChunk` / 结构化帧 | 原文是字节，表示层另算 |

`BytesChunk` 带 `framing`（raw / framed）、`boundary`（whole / continuation），
`LostUnit` 记录丢失单位。**这正是 elab 从"行数组"升级到"字节批次"需要的最小契约**。
我们不需要 `FlowEnvelope` 的泛型能力，但必须保留四个语义：**方向、纪元、序号区间、缺口**。

### 1.3 RawData 能力清单（用户可视化）

实读 `Lissio-Client/src/components/displays/rawdata/**` 与
`src/lib/buffers/rawDataViewStore.ts`，可迁移的完整交互面：

- **三种视图**：字节网格（8 字节一组，带偏移列）、按行查看、**ANSI 终端**；
- **四种表示**：HEX / ASCII / UTF-8 / GBK；HEX 可按字节类别着色；
- **方向过滤**：all / rx / tx；每行带方向符号与颜色；
- **时间戳与偏移**：可切换显示；行高固定 22px，配合虚拟列表；
- **搜索**：按文本/HEX 过滤；
- **发送面板**：文本/HEX、行尾（none/LF/CR/CRLF/TAB）、历史、严格 HEX 校验、
  文件发送；`SendFormat = ascii|utf8|gbk|hex`；
- **终端细节**：`AnsiStreamParser` 是完整状态机（`ground/escape/charset/csi/osc`），
  支持 SGR 颜色、`\r` 覆写、`\b`、`\t`、光标移动/清屏，以及 **UTF-8/GBK 流式增量解码**；
- **性能**：`useVirtualizer` 只渲染可视行；缓冲区按 Transport 引用计数共享；
  字符串历史只保留 1000 行且"值变化才记录"。

这套交互**不依赖 Tauri**，是纯浏览器代码，可在 `cockpit/web` 与 DSH 面板复用。

### 1.4 协议引擎

- **JustFloat**（`Lissio-Core/crates/protocol/protocol_float/src/justfloat.rs`）：
  N×4 字节小端 float + 尾 `00 00 80 7F`（`+∞` 的小端形态），按帧长自动推断通道数；
  支持 `split_aligned` 与 `take_pending`（半帧留待下一批）。
- **FireWater**：ASCII 逗号分隔 float + `\n`，同样自动通道检测。
- **RawData**：不解码，原样呈现。

两者算法很小（几十行），**按算法重写为 Python/TS 比引入 Rust 引擎便宜得多**。

### 1.5 Agent 工具范式

`Lissio-Server/.../capabilities/docs/zh/tools-guide.md` 给 Agent 的硬要求：
先说结论 → 先读现状 → 小步执行 → 每步验证 → 不确定先问 → 写入需明确授权。
工具面以 `get_raw_data` / `send_bytes` / `send_string` / `inject_bytes` 为主，
`get_*` 只读、`send_*` 写入。elab 的 `elab_serial` 目前只有"写一行"，
缺口是**结构化读**与**等待/断言**，不是"再多一个发送接口"。

### 1.6 调研结论（一句话）

> Lissio 证明了"字节为真值 + 多表示投影 + 虚拟列表 + 流式 ANSI + 结构化 Agent 读写"
> 是可行且好用的组合；elab 应迁移这套**语义与算法**，沿用现有的单口单例、
> 轮询 HTTP 与分层边界，而不是复制它的运行时。

## 2. elab 现状盘点

### 2.1 内核里已有的四个角色（职责已经分得很清）

| 模块 | 角色 | 数据形态 | 落盘 | 事件流 |
|---|---|---|---|---|
| `services/elab/monitor.py` | 闭环判据（run 内一次） | 行文本 + 规则判定 | run `.jsonl` | 有（`serial/*`） |
| `services/elab/serialterm.py` | 无状态往返（写一条→读 600ms→关口） | 文本回显 | `serial-console.jsonl` | 无（C27） |
| `services/elab/serialconsole.py` | 手写通道留档 | TX/RX 记录（≤512KB/2000 条） | 独立 JSONL | 无（C28） |
| `services/elab/serialmon.py` | 常驻监视单例 | **仅按 `\n` 切分的行** | 不落盘 | 无（C31 / ICD §3.7） |

`serialmon` 的现状（`services/elab/serialmon.py`）：

- `MAX_LINES = 2000` 的 `deque`，元素只有 `{seq, text, t}`；
- 只用 `decode("utf-8", errors="replace")`，**有损**且**无法还原字节**；
- `write_through()` 只写不记账，**TX 不进数据面**；
- 无 `epoch`：关闭再打开后 `seq` 从 1 重来，旧游标会静默失效；
- **能力上只有"行"**：没有 HEX、没有方向、没有时间精度、没有搜索/清空。

### 2.2 HTTP 面与自描述

`cockpit/server.py` 现有串口端点：

| 方法 | 路径 | 现状 |
|---|---|---|
| GET | `/api/serial/monitor?after=N` | 返回 `lines/seq/covered/gap/active` |
| POST | `/api/serial/monitor` | 仅 `open` / `close`，open 前查闭环 409 |
| POST | `/api/serial` | `data/newline/hex`；监视中路由进会话，否则无状态往返 |
| GET | `/api/serial/console?limit=N` | 手写通道留档尾部 |
| GET | `/api/capabilities` | `serial.monitor` 快照、`meta.steps/plans/channels` |

自描述已就位：`STEP_META` / `KERNEL_PLANS` 是"业务词汇唯一事实源"，工具层只渲染。
**新增串口词汇（视图、表示、编码、解码器、行尾）也必须进 `capabilities.meta.serial`**，
否则就是在工具层写死业务名词（违反 AGENTS.md 规则 1/4）。

### 2.3 前端现状

- **`cockpit/web`（内核自带完整驾驶舱）**：`EvidenceRail.tsx` 已有"打开/关闭监视 +
  600ms 轮询 + `gap` 提示 + 写穿会话"的完整闭环，但渲染仍是**单色文本行**
  （`logs.local("serial", ln.text)`），没有方向、字节、表示切换。
- **DSH 插件（`packages/dsh-elab-cockpit`）**：串口通道只是"文本日志尾"，
  且发送回调是 **stub**：

  ```tsx
  // src/adapters/dsh-web/CockpitPane.tsx:520
  serial={channel === 'serial' ? { writable: true, port: 'auto', baud: 115200, onSend: () => {} } : null}
  ```

  → 面板上敲串口命令**不会发出任何字节**，且端口显示是写死的 `auto`。
  这是 P1 必须修的缺陷，不是"未来优化"。

### 2.4 Agent 工具面

现有 `elab_serial`（`domain/tools.ts` 契约 / `adapters/dsh-tools/serial-ops.ts` 实现）参数 `project/data/baud`，
`allowAgentWrite()` 后才可用，走 `POST /api/serial`。**缺**：

- 读（`tail`/字节批次/方向过滤/gap）；
- 等待/断言（按正则或字节模式等一条，超时要能说"等到没有"）；
- 监视会话的打开/关闭（否则"写一条看回显"只能靠 600ms 往返，读不到持续输出）。

### 2.5 必须继续守的约束

| 约束 | 内容 | 对本方案的含义 |
|---|---|---|
| **N5** | 串口物理独占 | 监视会话仍是**单例**；open/run 双向 409 保留；Agent 开监视必须可回收 |
| **C17** | 事件流单写者 | 字节流**绝不**写进 run 事件流 |
| **C27** | 写通道无状态往返 | `POST /api/serial` 非监视态行为不变 |
| **C28** | 留档独立、有上限、会滚动 | 录制（K5）另起文件，不复用 console 的滚动语义 |
| **C31** | serialmon 单例/自愈/写穿/不落盘 | 新增能力必须沿用这三道防身 |
| **C24** | SSE 合并判据 | 本方案 P1/P2 **不新增 SSE topic**，绕开该风险面 |
| **C34** | 默认端口 8333 | 不变 |

## 4. 融合原则（先定规矩，再谈实现）

### 4.1 原文为真

**字节是唯一真相；行文本、HEX、ASCII、终端画面都是投影。**
投影可以丢、可以换编码、可以重放；字节环不能。由此推出：

- 新端点返回 `data_b64`；`render` 只是**附加字段**，不是替代品；
- 行视图继续由字节流增量解码得出，保证旧接口语义不漂移；
- 终端视图在**客户端**做增量解码（多字节字符跨批次时必须保持解码器状态）。

### 4.2 传输不动

P1/P2 继续用 **GET 轮询**（现有 600ms，可降到 250ms）。理由：ICD §3.7 已把
"监视不产生事件"固化为契约；新增 SSE topic 会同时触碰 C18（两端白名单）与
C24（合并判据）两个事故高发点。**等数据面稳定后，若要更低延迟，再加
`GET .../bytes?wait_ms=...` 的长轮询**（仍是 HTTP、仍不进事件流）。

### 4.3 分层不动

| 关注点 | 归属 | 说明 |
|---|---|---|
| 字节采集、环、序号、纪元、清空、TX 记账 | `services/elab/serialmon.py` | 业务层 |
| HTTP 契约、能力自描述 | `cockpit/server.py` | 业务层 |
| 完整可视化工作区 | `cockpit/web` | 业务层（内核自带前端） |
| 窄栏面板、Agent 工具 | `packages/dsh-elab-cockpit` | **工具层**，只经 HTTP ICD |
| 解码算法 | `services/elab/`（无状态纯函数）+ 新端点 | 业务层，供 web 与 agent 共用 |

**禁止**：插件 import 内核源码、读写 `.work/` 文件、按端口猜测会话状态。
新增端点必须同步进 `routes.ts` 白名单与 `boundary.test.mjs` 的可见面。

### 4.4 自描述优先

`capabilities.meta.serial` 由内核声明视图/表示/编码/行尾/解码器清单，
插件与 web 只渲染。新增解码器时**只改内核**，工具层零改动。

### 4.5 兼容优先

- 现有 `GET /api/serial/monitor` 的 `lines`、`seq`、`gap` **不改语义**；
- 新字段一律**追加**（`epoch`、`chunk_seq`、`covered` 等）；
- `tests/test_serialmon.py` 现有 13 个用例**必须全绿**，再新增用例；
- `newline`/`hex` 旧参数保留，新参数 `format`/`eol`/`encoding` 并存（旧参数是别名）。

### 4.6 许可与署名

按 Apache-2.0 §4：保留版权与 NOTICE、标注修改。**优先按算法重写**（Python/TS），
不整文件复制 Rust；确实移植的 TS 文件（如 `ansiParser`）在文件头写明
"Ported from Lissio (Apache-2.0), original: <path> @ <commit>"。

## 5. 目标能力分层

### K1 内核字节面（P1，必做）

| 项 | 设计 |
|---|---|
| 环形缓冲 | `MAX_BYTES = 1 MiB` + `MAX_CHUNKS = 4096`，双上限防"1 字节批次"把内存撑爆 |
| 批次 | 每次 `read()` 的原始字节为一条 `SerialChunk`；TX 在 `write()` 成功后同构入环 |
| 序号 | `chunk_seq` 会话内单调；行序号 `seq` **保持独立**（旧接口不变） |
| 纪元 | `epoch` 每次 open 自增；前端/Agent 发现变化即重置游标 |
| 缺口 | `covered`（被挤掉的批次数）+ `gap = first_seq - after - 1`，只报告不抹平 |
| 清空 | `clear` 保留 `seq/epoch` 单调，把被清内容计入 `covered`（客户端会看到 gap） |
| 暂停 | `pause/resume` 可选（P2）：暂停只停止入环，仍继续读口，避免设备侧阻塞 |
| 写穿 | 监视中 `write()` 成功即记录 TX 批次；失败不记录，返回 0 语义不变 |

### K2 可视化（P1 基础 + P2 终端）

| 子项 | 归属 | 说明 |
|---|---|---|
| K2a 完整串口工作区 | `cockpit/web` | 三种视图 + 四表示 + 方向/时间/偏移 + 搜索 + 发送面板 + 清空/暂停 |
| K2b 插件窄栏 | `packages/.../dsh-web` | 紧凑单行流（方向符号 + HEX/ASCII 切换）+ 发送框**真正接通** |
| K2c ANSI 终端 | 两处共用 | 移植 `AnsiStreamParser` 为独立 TS 模块；CSS 用等宽 + 固定行高 |
| K2d 波形（P3） | `cockpit/web` 主，插件可出火花线 | Canvas 2D 先做；uPlot 仅在需要缩放/联动时再评估 |

> 主可视化放 `cockpit/web` 而不放 DSH 右栏：右栏宽度有限，字节网格与波形需要横向空间。
> 插件负责"Agent 工作时随手看 + 随手发"，完整分析回浏览器。

### K3 协议解码与波形（P3）

- 内核提供**无状态** `POST /api/serial/decode`：输入原始字节（base64）或环区间，
  输出 `frames/samples/channels/issues/truncated`；
- 首批解码器：`justfloat`（尾 `00 00 80 7F`）、`firewater`（ASCII CSV + `\n`）、
  `raw`（不解码，用于对照）；
- 波形渲染在客户端；解码器注册表进 `capabilities.meta.serial.decoders`；
- Agent 可直接对一段字节调用 decode，拿到"第 3 通道最大值/样本数"这类可断言结果。

### K4 Agent 工具面（P1 读 + P2 等/监视）

| 工具 | 权限 | 语义 |
|---|---|---|
| `elab_serial`（扩展） | `allowAgentWrite` | 发送：`format=text|hex|base64`、`eol=none|lf|cr|crlf|tab`、`encoding=utf8|gbk` |
| `elab_serial_read`（新） | 只读 | 按游标读行或字节批次：`after/dir/limit/render/search/epoch`；返回 `gap/covered/next_after` |
| `elab_serial_wait`（新） | 只读 | 轮询 + 匹配（正则或 HEX 模式），返回命中批次与上下文；超时如实说"没等到" |
| `elab_serial_monitor`（新） | `allowAgentWrite` | `open/close/status`；open 必须带 `lease_s`（默认 120，上限 600），超时无 `tail` 自动关闭 |
| `elab_serial_decode`（P3） | 只读 | 对环区间或给定字节调用内核解码 |
| `elab_serial_capture`（P3） | `allowAgentWrite` | 导出有界 JSONL（默认最近 5000 批次/5 MiB），返回文件路径与统计 |

**Agent 租约**（D3）：Agent 打开的监视会话若不关闭会一直占口，直接违背 N5 的可用性。
建议内核在 `open` 时接受 `owner`/`lease_s`，`tail`/`bytes` 访问即续租；
租约到期自动 `close` 并在响应中带 `closed_reason="lease_expired"`。
人类打开的会话不设租约。

### K5 证据与录制（P3）

- 显式录制才落盘：`POST /api/serial/capture {action:"start"|"stop"|...}`；
- 文件 `.work/.cockpit/serial-capture-<epoch>-<ts>.jsonl`，有界（默认 5 MiB，超出停止并标记）；
- 每条记录：`{seq, t_us, dir, bytes_b64}`，**不落文本投影**（可重建）；
- 与 console 留档的区别：capture 是"证据"（完整、有界、可回放），console 是"我敲过什么"（会滚动）。

## 6. ICD 增补（可直接照此实现）

### 6.1 不变项

- `GET /api/serial/monitor?after=N` 的 `lines/seq/covered/gap/active` 语义不变；
- `POST /api/serial/monitor` 的 `open/close` 与 409 文案不变；
- `POST /api/serial` 的 `data/newline/hex` 行为不变；
- 串口输出**仍不进 SSE**，`SSE_TOPICS` 不新增。

### 6.2 `GET /api/serial/monitor/bytes`

```http
GET /api/serial/monitor/bytes?after=0&dir=all&limit=256&render=none
```

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `after` | int | 0 | 已收到的最大 `chunk seq` |
| `dir` | `all|rx|tx` | `all` | 方向过滤 |
| `limit` | 1–256 | 256 | 本批最多返回条数 |
| `render` | `none|hex|ascii|utf8|gbk` | `none` | 附加 `text` 字段；`none` 只返回 b64 |

响应（**新增字段追加在旧快照上**）：

```json
{
  "active": true, "epoch": 3, "project": "p1", "port": "COM10", "baud": 115200,
  "backend": "pyserial", "chunk_seq": 812, "covered": 0, "gap": 0,
  "chunks": [
    {"seq": 811, "t_us": 1723456789012, "t": "10:12:34.567", "dir": "rx",
     "n": 7, "data_b64": "AAABAAIAAwA=", "text": "……"}
  ],
  "has_more": false, "next_after": 812
}
```

约定：

- `gap = first_returned_seq - after - 1`（`after=0` 也参与），只报告；
- 空会话返回 `{active:false, epoch:0, chunks:[], gap:0}`；
- `render` 是逐批独立解码，**跨批多字节字符可能被替换**；终端视图必须用
  `render=none` 并在客户端保持流式解码器；
- `limit` 截断时 `has_more=true`，客户端按 `next_after` 继续拉。

### 6.3 `POST /api/serial/monitor` 扩展动作

```json
{"action":"open","project":"p1","port":"","baud":0,"owner":"human|agent","lease_s":0}
{"action":"close"}
{"action":"clear"}                    // P1
{"action":"pause"|"resume"}           // P2（可选）
```

- `clear` → `{ok, cleared_chunks, cleared_lines, epoch, chunk_seq}`；
- `pause` → 停止入环但继续读；`resume` → 继续入环，中间被跳过的批次计入 `covered`；
- `lease_s>0` 仅对 `owner=agent` 生效；人类会话忽略该字段；
- 所有动作仍受 `_serial_blocker` 保护；`open` 遇闭环占用返回 409。

### 6.4 `POST /api/serial` 扩展

保留 `data/newline/hex`，新增（两者并存，旧参数是别名）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `format` | `text|hex|base64` | `hex:true` ≡ `format=hex`；`newline` 仅对 text 生效 |
| `encoding` | `utf8|gbk` | text 模式的编码，默认 utf8 |
| `eol` | `none|lf|cr|crlf|tab` | 默认 `crlf`（与现状 `DEFAULT_EOL="\r\n"` 一致）；`newline:false` ≡ `eol=none` |
| `read_ms` | 0–10000 | 非监视态往返的读取窗口，不变 |

返回仍是同一形状（`ok/port/baud/written/payload_bytes/echoed/error/via?`），
`via` 在监视态为 `"monitor"`。

### 6.5 `POST /api/serial/decode`（P3）

```json
{"decoder":"justfloat","input_b64":"...","window_ms":500,"max_frames":2000}
```

响应：

```json
{"ok":true,"decoder":"justfloat","channels":3,
 "frames":[{"t_us":0,"values":[1.5,-2.0,0.25]}],
 "samples":[{"channel":0,"t_us":0,"value":1.5}],
 "issues":[],"truncated":false,"consumed_bytes":12,"tail_bytes":0}
```

- **无状态**：不解码会话，不缓存；半帧留在响应 `tail_b64` 里由调用方续传；

- `issues` 记录"帧长不是 4 的倍数/尾标记缺失/非数值"等，**不静默丢**。

### 6.6 `POST /api/serial/capture`（P3）

```json
{"action":"start","project":"p1","max_bytes":5242880}
{"action":"stop"}
{"action":"status"}
```

`start` 从当前 `chunk_seq` 起录；`stop` 返回 `{path, chunks, bytes, truncated}`。

## 7. 数据模型

### 7.1 内核（Python，`serialmon._Session`）

```python
class _Session:
    epoch: int                 # 每次 open 自增（模块级计数器）
    started_mono: float        # 会话起点，用于 t_us
    chunks: deque[dict]        # {seq,int; t_us,int; t,str; dir,str; bytes,bytes}
    chunk_seq: int             # 单调
    chunk_covered: int         # 被挤掉的批次数（gap 证据）
    chunk_bytes: int           # 当前占用字节
    paused: bool
    owner: str                 # human | agent
    lease_s: int
    last_access_mono: float    # 租约续期用
```

不变：`lines/seq/covered/stop/error/alive/thread/wlock`。
新增 `rlock` 保护"入环 + 计数 + 挤出"的复合操作。

### 7.2 前端（TypeScript，`packages/.../domain/icd.ts` 与 `cockpit/web/src/api/types.ts`）

```ts
export interface SerialChunk {
  seq: number;
  t_us: number;
  t: string;                 // "HH:MM:SS.mmm"
  dir: 'rx' | 'tx';
  n: number;
  data_b64: string;
  text?: string;             // 仅 render != none 时出现
}
export interface SerialBytesTail {
  active: boolean;
  epoch: number;
  project?: string; port?: string; baud?: number; backend?: string;
  chunk_seq: number;
  covered: number;           // 被挤掉的批次数
  gap: number;
  chunks: SerialChunk[];
  has_more: boolean;
  next_after: number;
}
```

### 7.3 两个游标的纪律

| 游标 | 端点 | 重置条件 |
|---|---|---|
| 行游标 `after` | `/api/serial/monitor` | `epoch` 变化、`clear` 后 `gap>0` |
| 批次游标 `after` | `/api/serial/monitor/bytes` | `epoch` 变化、`clear` 后 `gap>0` |

**前端与 Agent 都必须先比较 `epoch`，再把 `after` 归零**；否则重开监视后
旧游标会静默看不到数据（这是 Lissio `connection_epoch` 存在的原因）。

## 10. 风险与决策

### 10.1 轮询 vs SSE vs 长轮询

- 现状 600ms 轮询在 115200 波特率下（≈11.5 KB/s）足够；
- SSE 会引入 C18/C24 两个已知事故面，收益只是延迟；
- **决策**：P1/P2 维持轮询；若实测延迟不够，加 `wait_ms` 长轮询（≤2000ms），
  不新增 topic。

### 10.2 内存与带宽

- 批次上限 1 MiB + 4096 条，双上限防碎片化；
- base64 膨胀 33%；单批 256 条 / 256 KiB 上限；
- Python 序列化 256 KiB/批在本地 loopback 无压力；超过则分页（`has_more`）。

### 10.3 编码与流式解码

- 内核 `render` 是逐批独立解码，**只服务 Agent 的"看一眼"**；
- 终端视图必须客户端流式解码（`TextDecoder({stream:true})`，UTF-8/GBK）；
- GBK 在 Node 侧支持依赖 ICU，**Agent 不本地解码**，一律让内核 render。

### 10.4 ANSI 移植

- 直接移植 `ansiParser.ts`（Apache-2.0，带头注释）；
- 输出只经 React 文本节点/CSS 颜色，**不用 `dangerouslySetInnerHTML`**，
  避免设备输出注入 DOM；
- 控制序列限长（OSC 等设上限），防异常流拖死解析器。

### 10.5 波形

- 先 Canvas 2D（无新依赖，符合 N3 的"前端构建产物入仓"）；
- uPlot 仅在需要缩放/多图联动时评估；插件右栏只做火花线。
- 抽点策略：按像素列聚合 min/max，避免 1 万点全画。

### 10.6 许可证

- Lissio 为 **Apache-2.0**；elab 仓库为 MIT（插件 package 亦 MIT）；
- Apache-2.0 → MIT 的分发是允许的，但必须保留版权/NOTICE/修改声明；
- 新增 `NOTICE`（或并入现有）：
  `Portions ported from Lissio (https://codeberg.org/Horldsence/Lissio), Apache-2.0, commit edf17b5.`
- 重写算法仍建议标注来源，降低后续审计成本。

> **更新（v4.0.0）**：本仓协议已由 MIT 改为 **Apache-2.0**（内核、随仓插件、官方适配包），
> 与上游 Lissio 的 Apache-2.0 对齐，省掉一次跨协议再分发。v1.0.0 – v3.1.0 已按 MIT 发布，

> `NOTICE` 追加协议沿革说明。

### 10.7 N5 与 Agent 租约

- 最大风险不是"读不到"，而是"Agent 忘了关，人跑不了闭环"；
- **决策**：Agent 开监视必须带 `lease_s`，`tail` 续租，到期自动关；
- 人类会话不设租约；`close` 幂等不变；`/api/run` 遇监视占用仍 409 指名道姓。

## 13. 决策记录（2026-10-31 已确认）

> 本节为评审确认结论，后续实现以此为准；§9 的 P1→P2→P3 仍按顺序落地并分批验收。

| # | 决策 | 结论 | 对实现的影响 |
|---|---|---|---|
| D1 | 本期范围 | **P1–P3 全做**，按三期分批验收 | §5 的 K1–K5 全部进入本期；§9 三个里程碑全部交付 |
| D2 | Agent 开监视 | **`allowAgentWrite` + `lease_s` 租约** | 内核 `open` 接受 `owner/lease_s`；`tail`/`bytes` 访问即续租；到期自动关闭并标 `lease_expired` |
| D3 | 解码/波形 | **本期一起做**（P3） | `serialcodec.py`、`POST /api/serial/decode`、Canvas 波形进入本期 |
| D4 | 可视化落点 | **Web 完整 + 插件紧凑** | `cockpit/web` 做完整工作区；插件右栏只做紧凑流 + 发送框（P1 先修 stub） |
| D5 | 写路径健壮性 | **pyserial 写超时 2s + 异常落 `ok:false`** | 断链/拔线时 pyserial `write` 会无限阻塞（实测把 HTTP 请求挂死 10s+，界面表现为"点发送毫无反应"）→ `write_timeout=2.0`、去掉无上限的 `flush()`、`write()` 捕获异常返回 0；`close` 也随之不再被 `wlock` 卡住 |
| D6 | 无硬件端到端自测 | **支持 URL 端口（`loop://` 等）** | `SerialIO.open` 见 `"://"` 走 `serial_for_url`（`Serial()` 不认 URL）；`loop://` 写出即回读成 RX，整条数据面（TX 入环/行投影/解码/四视图）可离线闭环验证。测试见 `tests/test_serialport.py` |
| D7 | 终端 ANSI 解析 | **SGR 引导符 `[` 不计入参数缓冲区** | 修 `cockpit/web/src/serial/ansiTerminal.ts`：`[` 的码位恰好落在终止区间 `@–~`，旧实现一收到就"终止"，导致 `ESC[33m` 被漏成 `33m`、`ESC[0m` 漏成 `0m` 正文，颜色也从不生效 |
