# 设计约束（C1–C32）—— 本仓库的"为什么"

> 每一条约束都来自一次真实事故或一次可复现的实验，且已固化为代码 / 测试守卫。
> 本表是唯一权威来源（自 V1.0.0 起自 README §10 迁入并补齐 C32）。
> 配套阅读：[CHANGELOG](../CHANGELOG.md) · [事件契约 ICD](ICD_cockpit_events.md) · [驾驶舱技术方案](技术方案_闭环驾驶舱.md)。

## 构建 / 工具链（C1–C16）

| # | 约束 | 依据 |
|---|---|---|
| C1 | B 类必须挂 `inject`；要**清 `CMAKE_C_LINK_FLAGS`** | 工程与 elab 用了不同名的链接变量 → 两份都拼进链接行 |
| C2 | `add_compile_options` **必须拆独立参数** | 整串会被当成单个带引号参数 → gcc 报 `unrecognized -mcpu target` |
| C3 | inject **不盖 defines / include** | 工程自带的准确，再注入只制造双源 |
| C4 | `guard` **不能依赖 git**，用文件树快照 | 示例工程不是 git 仓库 |
| C5 | A 类也必须挂 inject（为补工程自述约定）；`.elf` 后缀进**通用**工具链 | 接管后产物静默改名 `TEST` |
| C6 | hex/bin **由 elab 统一产出** | 有的工程没有 POST_BUILD objcopy |
| C7 | `fpu` 需支持 `none` | M3 无 FPU，不能产出 `-mfloat-abi` |
| C8 | `--json` 下必须静默人类日志 | 否则 stdout 被进度行污染，JSON 解析失败 |
| C9 | interface cfg 优先级：**探针 > 芯片** | interface 属于探针，与芯片正交 |
| C10 | AT32 的 `guard` 也要用快照 | 与 C4 一致，避免静默跳过 |
| C11 | 增量构建无 relink → `memory` 段为空；内存口径以 `size` 为准 | 无链接则无 `--print-memory-usage` |
| C12 | `elab flash` **必须回显 openocd 证据行** | 只打一行摘要等于把证据换成信任 |
| C13 | 必须有非交互 `debug --verify` | 交互式 gdb 进不了 CI，也无法"证明"链路通 |
| C14 | debug 的 openocd 后台进程必须 `finally terminate()` | 否则占住 3333 端口 |
| C15 | SVD：**chip 声明文件名 + host 声明搜索根** | 禁止在 chip.yaml 写主机绝对路径 |
| C16 | CI 与本地共用同一份 `matrix.yaml` | 否则必然"本地绿、CI 红" |

## CI（C22–C23）

| # | 约束 | 依据 |
|---|---|---|
| C22 | CI **不许写死产物路径**；产物路径必须由 `elab ci --json` 的 `build` 步骤自报 | 文件基名**按工程定**（`at32_test` → `TEST.*`，`at32f421g8u7` → `AT32F421G8U7.*`）。写死 glob 的后果是**绿着却没有固件产物**（`if-no-files-found: warn` 静默降级）。自报之后接入新工程无需改 workflow |
| C23 | 门禁为 success 却**零产物**，收集步骤必须 `exit 1` | "假绿"比"红"危险：绿着、工件为空，问题被带到下一次。门禁本身失败时只告警（不重复报错） |

## 事件流 / 驾驶舱（C17–C21，C24–C32）

| # | 约束 | 依据 |
|---|---|---|
| C17 | 事件流**单写者**：只有 `elab run --emit-events` 一个进程写；`seq` 分配与落盘必须在**同一把锁**内 | 唯有如此，磁盘上的事件才恒为连续 `seq` 前缀 —— 重放/断线续传才成立。取消时父进程补 `run/cancel` 是**唯一豁免**（前置条件：写者已死） |
| C18 | SSE 是**命名事件**：新增 topic 必须**两端同时**改 `SSE_TOPICS` + `KNOWN_TOPICS` | `EventSource.onmessage` 只接收**没有 `event:` 字段**的帧；漏一个 topic = 该 topic 全部事件在浏览器里静默消失。**实测事故**：漏了 `proc/stdout-batch` → 实时编译日志 100% 不可见（run 结束后重放却正常，极易误判）。守卫：`test_known_topics_covers_server_emitted` |
| C19 | HTTP/1.1 keep-alive 下，**每条请求**都要重置 handler 的实例级标志 | 一个 handler **实例**服务一整条**连接**。`_sent_headers` 不重置 → 第二条请求起一个字节都不写：页面卡 `interactive`、控制台**零报错**，而 curl（每次新连接）全绿 |
| C20 | 日志**不进 React 树**；且"列表为空"的判据必须能识别"**被清空**" | 上万行走进 reconciler 会卡死；`clearAll()` 既不改"被裁计数"也不满足"指针越界"，只按这两条判会**既不重建也不追加** → 切工程后显示的还是上一次的日志 |
| C21 | `/api/runs.active` 只能是**活着的** run；登记簿 ≠ 活动列表 | 登记簿要保留已结束的条目（SSE 靠它判"已结束→重放完收尾"），但把它当活动列表返回会让前端挂到**最早那条已结束的 run**（症状：跑新 run 显示旧 run 的日志） |
| C24 | SSE 的**合并**判据只能用"**是进程输出**"（`is_batched`），**不许**用落盘通道分类 `is_activity` | 落盘通道把 `serial/*`/`stream/*` 也算了进去，而"合并"是**传输层**动作。**实测事故**：`serial/open`/`close`/`closed-loop` 没有 `line` 字段 → 被合并成一行**空文本** → 浏览器什么都收不到，且**只在实时路径**复现。守卫：`test_live_sse_keeps_domain_events_as_named_frames`（已做变异检验） |
| C25 | 背压丢弃**必须留痕**（`stream/overrun`），且 `stream/closed` 属**控制帧**、与 `run/*` 同级不可丢 | 只 `dropped += 1` 而不发事件 = 服务端记了损失、界面一个像素没变。`stream/closed` 的 `is_activity()` 为真，队列满时会被当可丢事件丢掉 → 浏览器唯一的"run 结束了"信号没了 → 界面**永远显示"运行中"**（症状是"卡住"不是"报错"） |
| C26 | 只读预览（`--dry-run` / `GET /api/plan`）**不许另拼一份命令** | 预览的全部价值是"我说的就是待会儿真跑的"；两处分叉是**静默**的。故 `builder.build_command()` 抽成函数、`flash`/`debug` 用 `allow_missing_elf=` 开预览口子 —— 命令构造始终只有一处 |
| C27 | 串口写通道用**无状态往返**（open→write→read→close），**不做常驻会话**；且**不发射事件** | 串口**独占**：常驻会话会与 monitor 互斥，持口线程僵死没人释放。无状态把占用压进一次请求，**天然与 monitor 串行**。★ 与 `flash`/`debug_verify`/`monitor` **互斥**（409 指名道姓，否则用户只看到 `ERROR_ACCESS_DENIED` 会去拔插） |
| C28 | 手写通道的 TX/RX 落**独立的** console 留档（`serial-console.jsonl`），**绝不**写进 run 事件流；留档**有上限、会滚动**（尾部 N 条 + `os.replace` 原子替换）；CLI 与界面写**同一份** | 写进 run 流会同时破坏"每条事件带 run"与**单写者**（C17）。**正因为它会改写，它就不是 state**：不可当验收判据、不可做增量同步。实测边界：`elab loop` 五步全绿后留档条数**不变**（两条道互不污染） |
| C29 | 一键适配**真写出**新 `projects/<name>.yaml` 后，服务端必须**热重载 Config** | 服务进程的 `Config` 启动时固化 —— 不重载则新工程对 `/api/projects` 与 `/api/run` **双双不可见**，症状"写入成功、卡片永远不出现"（**真浏览器实测抓出**。守卫：`test_adapt_write_creates_new_project_file`） |
| C30 | UI 的「跑全闭环」必须**显式传步序**；后端 `DEFAULT_STEPS = doctor+build` 只是 API 默认值，**不是**全闭环 | 不传 steps 时只跑 doctor+build —— 按钮写着"全闭环"、跑完编译就停，行为与承诺**静默背离**（实测抓出）。修在**前端**（`fullLoopSteps()`）；空闲骨架与按钮同源 |
| C31 | 常驻串口监视会话（serialmon）必须：**单例 + 一键显式关闭**、**读线程异常自愈**、**写通道路由进会话**；输出**不进 run 事件流也不落 console 留档** | N5 物理事实不因 UI 需求改变。输出两条道都不走：进事件流破坏 C17，落留档被设备心跳撑爆。★ 实现坑：读线程**绝不能**用 `with self.io`（`__enter__` 二次 open 同一个口 → 撞自己持有的独占句柄 ACCESS_DENIED，真机首测抓出）。互斥双向 409 |
| C32 | stdout 被重定向 + GBK 区域编码会崩 CLI/服务：非 UTF-8 stdio 一律在**包入口** `reconfigure(utf-8, replace)` | 双击 `cockpit.cmd`（`> log 2>&1`）场景下 Python 按区域取 GBK，横幅 `✓/✗` 编不进去 → `UnicodeEncodeError` 把服务打崩（起完监听即死、UI 不弹）。★ 教训：**验收环境的 env 与用户双击环境不同**（bash 带 `PYTHONUTF8=1`，Explorer 没有）——关键路径必须 `env -u` 剥变量再验 |

## OTA 双镜像（C33）

> 首个落地工程：`at32f421g8u7_workbench`（Bootloader 18K @0x08000000 + APP 44K @0x08004800 + 元数据页）。M1/M2 是业务工程实测教训（其 CMakeLists 注释实锤），elab 框架侧的固化即本条。

| # | 约束 | 依据 |
|---|---|---|
| C33a | **APP 必须用 bin + 显式地址烧录**，禁止 `program app.elf`；`flash.images` 里 bin 项**必须**声明 `address`（plan 层 fail-fast） | openocd 对 elf 的 program 会从**擦除粒度边界向下对齐**起擦：APP LMA 0x08004800 被对齐到 0x08004000，覆盖 Bootloader 尾部 2KB（M2 实测）。bin + 显式地址不做向下对齐 |
| C33b | 双镜像烧录 = **一次 openocd 会话**串多个 `-c "program ..."`，收尾统一 `reset run` + `shutdown`；预览与实跑共用 `_flash_images()`（C26 延伸） | Boot 与 APP 必须作为原子整体落 Flash——分会话时第一镜像烧完的复位窗口把芯片带到半成品态；预览若因"镜像还没 build"而省略 program 就是误导（**命令构造与存在性检查解耦**，`exists` 只是信息不是条件） |
| C33c | B 类 OTA 工程必须 `build.link_channel: c_flags`：inject 盖章走 `CMAKE_C_LINK_FLAGS`，**同时清空 `CMAKE_EXE_LINKER_FLAGS`** | 业务 bootloader 的 `string(REPLACE "-T .../APP.ld" ...)` 防身只清 C flags 通道——EXE 通道盖章会与 target 的 `-T BOOT.ld` 形成双 -T，两个 SECTIONS 合并 → .init_array/.data 布局异常 → printf 内部跑飞（M1 实测）。而 gcc.cmake（工具链文件，project() 前）已在 EXE 通道盖过章：**不清空则双份 nano.specs** → `attempt to rename spec 'link' to already defined spec 'nano_link'`（接入实测抓出）。清空后 bootloader 链接行 = REPLACE 后的 C flags + 自己的 target options = 单 `-T BOOT.ld`，零改动业务工程（C4） |
| C33d | doctor 内存对账按**镜像级口径**：各镜像 ld 的 region **⊆ 芯片物理范围** + **flash 分区互斥**（RAM 不查）+ **bin address == 其 ld 的 FLASH 起点** | BOOT 18K / APP 44K 都 ≠ 芯片 64K，逐字节相等口径必然误报。RAM 两个镜像声明全量是 OTA 惯例（boot/app 不同时运行）不可查互斥；bin 烧错位 = 跑飞，address 与 ld 起点的一致性是零成本防线 |
| C33e | 镜像模式下 debug **跳过 gdb `load`** | load 按 APP elf 段擦写 Flash，与 program app.elf 有同样的向下擦除风险（M2）；闭环顺序 flash 在 debug 前，固件已在位，`reset halt` 断点即可 |
| C33f | 多镜像工程的 build 内存表来自**最后完成链接的 target**（boot 或 APP 不定），APP 精确占用以 `.map` 为准 | `--print-memory-usage` 逐 exe 输出、同名 region 互相覆盖，是解析器的既有限制；为显示层引入 per-exe 区分不值得复杂化（保守方案），如实注明即可 |
