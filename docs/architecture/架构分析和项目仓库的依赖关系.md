# 架构分析和项目仓库的依赖关系

> 核对日期：2026-11-02
> 核对方式：逐条对照源码（`services/elab/**`、`cockpit/**`、`packages/dsh-elab-cockpit/**`、
> `.github/workflows/**`）、`package.json`、GitHub API、npm registry 与线上市场目录
> （`awesome-dsh-plugin.com/catalog.json`）。本文只写**已核对**的事实；推断处明确标注。

## 1. 一句话结论

**内核是产品（Python 可独立运行），插件是遥控器（只通过 loopback HTTP 操作内核），
`packs/` 是芯片字典、`providers/` 是工具链字典（都是可插拔数据），UI 有两只但 API 只有一张。**

分层依赖严格单向：工具层 →（HTTP ICD）→ 业务层 →（`pack.yaml` / `provider.yaml` 协议）→ 数据层。
反向依赖（工具层 import 内核源码、内核 import 包/ provider 文件）被门禁测试拦截。

## 2. 分层总览

```

└───────────────┬───────────────────────────────────────────────┘
                │ 唯一合法缝隙：loopback HTTP ICD
                │   /api/*（命令）+ /api/events（SSE，运行事件）
┌───────────────┴───────────────────────────────────────────────┐
│ 业务层 services/elab/** + cockpit/server.py                     │
│  run 编排 / build / flash / debug_verify / serial / pkg / market │
│ 自带 Web UI：cockpit/web（Vite → dist，运行时不需要 Node）      │
└───────────────┬───────────────────────────────────────────────┘
                │ 只读 pack.yaml / provider.yaml 协议；不 import 包内文件
┌───────────────┴───────────────────────────────────────────────┐

└───────────────────────────────────────────────────────────────┘
        ↑ 固件与示例（业务层的一部分）：projects/*.yaml、
          examples/**、components/ota/**
```

## 3. 业务层（内核，唯一事实源）

### 3.1 模块职责（`services/elab/`）

| 模块 | 职责 |
|---|---|
| `run.py` | 闭环编排：按 plan 逐步 spawn、写事件日志、支持取消 |
| `plan.py` | 三档计划定义与步骤展开（basic / triple / loop） |
| `doctor.py` / `adapt.py` | 环境体检；工程探测与 `projects/<name>.yaml` 适配 |
| `builder.py` | CMake/Ninja 构建，解析进度与 RAM/FLASH 占用 |
| `flash.py` | openocd 烧录 + gdb 校验（`-batch` 序列，命中 `main` 判定） |
| `monitor.py` | 串口闭环判据（心跳/关键字） |
| `serialport.py` / `serialmon.py` | 端口枚举与串口监视（读流、批次、回放） |
| `serialterm.py` / `serialconsole.py` | 终端视图发送（格式/编码/行尾）、REPL 控制台 |
| `serialcodec.py` | 解码器：JustFloat（N×4 小端 float + `00 00 80 7F`）、FireWater（ASCII 逗号 + `\n`） |
| `pkg.py` / `market.py` | 适配包安装/校验；零服务器市场索引（packs + providers） |
| `provider.py` | 工具链 provider：manifest 校验、版本约束、注册表、`ResolvedToolchain` 解析、安装/卸载 |
| `lock.py` | `elab.lock.yaml`：已安装 packs/providers 的版本漂移检测 |
| `ota_layout.py` | 双槽布局与状态扇区解析 |
| `skillgen.py` | 生成平台 skill 文档（`stm32` / `at32` 等） |
| `config.py` / `version.py` | 配置与版本 |
| `_yaml.py` / `_winproc.py` | 零依赖 YAML 子集；Windows 进程细节 |

### 3.2 HTTP 面与「内核自描述」

`cockpit/server.py` 同时是 HTTP 面与**业务词汇的唯一宿主**：

- 自描述常量：`STEP_META`（步骤标签 + 通道）、`KERNEL_PLANS`（三档）、
  `SERIAL_META`（视图/解码器/特性）、`COCKPIT_VERSION`。
  插件与内核 Web UI 只**渲染**这些定义；改名/加步骤只改内核。
- 路由（实测 grep `server.py`）：
  - 读取：`/api/capabilities`、`/api/projects`、`/api/packs`、`/api/pkg/job`、
    `/api/runs`、`/api/plan`、`/api/serial/monitor[/bytes|/decoded]`、
    `/api/serial/console`、`/api/events`（SSE）。
  - 写入：`/api/run`、`/api/cancel`、`/api/pkg/*`、`/api/serial`、
    `/api/serial/monitor`（open/close）、`/api/serial/capture`、
    `/api/serial/decode`、`/api/adapt`。
- 端口：`DEFAULT_PORT = 8333`，**刻意避开 3333**（openocd 的 gdb server 固定占 3333）。

### 3.3 运行事件模型（run 的真相）

- 长任务绝不在 HTTP 进程里跑：`server.py` spawn `elab run --emit-events` 子进程，
  本进程只做「跟读只追加日志 + 转发 SSE + 取消」。
- 事件落盘：`<run>.jsonl`（`run/start`、`run/step-enter`、`run/step-exit`、
  `run/end`、`run/cancel`、`serial/*`）与 `<run>.proc.jsonl`（proc stdout/stderr）。
- 扇出：follower 线程按 seq 归并后推 `proc/stdout-batch`（100 ms 合并），
  结束补发 `stream/closed`；SSE 心跳 15 s。
- 关键纪律：`stream/closed` 是浏览器唯一的「run 结束」信号，列入**不可丢**事件。

### 3.4 内核自带 Web UI

- `cockpit/web/`：独立 Vite + React 工程，产物 `dist/` **已入仓**，
  `python -m elab cockpit` 直接托管，运行时不需要 Node（保住「只装 Python 也能跑」的卖点）。
- 与插件面板是**两套皮、一个后端**：不共享前端代码，各自消费同一张 HTTP 契约。

### 3.5 固件与示例（业务层延伸）

- `projects/f411.yaml`：工程描述、烧录镜像、串口参数（`elab` 的输入）。
- `examples/STM32F411CEU6`：FreeRTOS 应用（本次正弦波演示固件所在）。
- `examples/STM32F411CEU6/boot` + `components/ota/**`：双槽 boot、跳转、试运行确认
  （bank 记录 append-only + CRC32；`STATE_RUNNING` 有升级窗口）。

## 4. 数据层（芯片知识 + 工具链知识的唯一宿主）

### 4.1 适配包协议

`packs/official/st/stm32/pack.yaml`（当前 `packs/official/**` 里唯一的包）：

```yaml
schema_version: 1
name: st/stm32
vendor: st
platform: stm32
version: 0.1.0
requires:
  kernel_api: ">=1 <2"
  schema_version: 1
vendor_fingerprints:
  - generator: stm32cubemx
    gen_dir: stm32cubemx
    syms_var: MX_Defines_Syms
    project_glob: "*.ioc"
```

- 芯片参数（Flash/RAM/OTA 槽）、厂商指纹、平台坑位都只在这里。
- 内核**不 import 包内任何文件**，只按 `pack.yaml` 协议读 → 新厂商 = 新包，内核零分支。

### 4.2 市场索引

`market/index.json`（零服务器索引，包内容留在作者仓库）：

```json
{
  "schema_version": 1,
  "packs": [
    { "name": "artery/at32", "vendor": "artery", "platform": "at32",
      "version": "0.1.0", "status": "community", "license": "MIT",
      "requires": { "kernel_api": ">=1 <2", "schema_version": 1 },
      "chips": ["artery/at32f421g8"],
      "source": { "type": "git",
                  "url": "https://github.com/xkk6663/elab-pack-artery-at32.git",
                  "ref": "<commit>" },
      "sha256": "0669…" }
  ]
}
```

- 索引只记 name/version/source/sha256/requires/license；CI 用
  `elab pkg index --check` 拦漂移。工具链 provider 也登记在同一份索引里
  （`kind: "provider"`，`provider_api: 1`，含步骤清单与主机前提）。
- `packs/installed/`、`providers/installed/` 是用户安装落点，**被 `.gitignore` 排除**，不入库。
- 外置包（如 `artery/at32`）必须是独立 GitHub 仓，**不得**放进 `packs/official/**`；
  内容哈希按字节计算，包仓必须带 `.gitattributes`（`* -text`）。

### 4.3 工具链 provider（与芯片包分离）

`providers/official/espressif/idf/provider.yaml` 只声明「规范步骤怎么跑」，不含芯片参数：

```yaml
schema_version: 1
provider_api: 1
name: espressif/idf
version: 1.0.0
requires:
  kernel_api: ">=1 <2"
  host:
    - { key: tools.idf.python, check: file }
artifacts:
  elf: ${work_dir}/${name}.elf
  map: ${work_dir}/${name}.map
steps:
  build:
    cmd: ["${env:IDF_PY}", "${env:IDF_PATH}/tools/idf.py", "-B", "build", "-DIDF_TARGET=${chip.target}", "build"]
```

- 工程只写 `provider: espressif/idf@>=1 <2`；解析优先级为
  项目 `steps.<step>: tool:<name>` → provider `steps` → 无 provider 时的原生链。
- `monitor` / `doctor_deep` 永不由 provider 提供；缺步骤直接 `unavailable` 报错，不回退。
- `providers/installed/` 是安装落点（`.gitignore` 排除）；随仓只提交
  `providers/official/**` 与 `market/index.json`。
- 安装只落数据、不执行命令；版本用 `elab.lock.yaml` 锁定，`elab doctor --strict-lock` 可升为失败。

## 5. 工具层（DSH 插件）

### 5.1 插件内部分层（门禁 `test/boundary.test.mjs` 定义）

| 子层 | 目录 | 规则 |
|---|---|---|
| domain | `src/domain/**` | 纯函数状态归约，只准相对 import 同目录；零 I/O、零宿主、零框架 |
| app | `src/app/**` | `ports.ts` + `cockpit-service.ts` 是**唯一编排点**，只准 import domain 与互相 |
| adapters | `src/adapters/{kernel-http,kernel-process,dsh-tools,dsh-web,fs-store}` | 适配器之间**不得互相 import**；组装只在 `main.ts` / `host-app.ts` / `CockpitPane` |
| 入口 | `src/main.ts`、`host-app.ts` | 组装根，禁止被 `src/**` 反向 import |

级联规则 A：`src/**` 任何静态 import 不得指向 `services/elab/**` 或 `cockpit/**`
（唯一缝隙是运行时 fetch = loopback HTTP ICD）。

### 5.2 两个 UI 的真实关系

| | 内核 UI | 插件 UI |
|---|---|---|
| 位置 | `cockpit/web`（Vite → `dist/` 入仓） | `src/adapters/dsh-web/*.tsx`（React，esbuild → `lib/client.js`） |
| 运行环境 | 浏览器直接开 8333 | DSH 面板内嵌 |
| 数据来源 | `/api/*` + `/api/events` | 同一张 ICD（经 `adapters/kernel-http`） |
| 是否互相加载 | 否 | 否（插件**不加载**内核 `dist`） |

### 5.3 进程托管与环境包

- `adapters/kernel-process/host-process.ts`：发现/拉起内核、探端口、退出清理；
  内核过旧（缺 `capabilities.meta`）由面板提示同步，工具层不写业务兼容分支。
- `envpacks/manifest.json`：只记**官方上游直链** + 期望 sha256 + 注入的 `ELAB_*`
  环境变量（`ELAB_ARM_GCC_ROOT` / `ELAB_CMAKE` / `ELAB_NINJA` / `ELAB_OPENOCD`…）；
  插件**不内置二进制**，下载解到 `~/.dsh/elab/env/<packId>/<toolId>`。

### 5.4 构建产物与 npm 内容

- `npm run build` = `tsc -p tsconfig.host.json` → `lib/main.js`（宿主半）
  + `scripts/build-client.mjs`（esbuild）→ `lib/client.js`（浏览器半）
  + `verify:contract`（宿主/客户端契约校验）。
- `package.json#files` 白名单（发 npm 的内容）：
  `lib`、`envpacks/manifest.json`、`cordis.patch.yml`、`icon.svg`、
  `locale/*.json`、`README.md`、`screenshots.json`、`assets`。
- 当前 `package.json` **没有 `repository` / `homepage` / `bugs` 字段**（已核对）。

## 6. 一次闭环如何穿过四层

```
agent 调 elab_run(action="build")（工具层 adapters/dsh-tools/，契约在 domain/tools.ts）
  → cockpit-service 发 POST /api/runs（adapters/kernel-http）
    → cockpit/server.py 落 run/start，spawn `elab run --emit-events`
      → 子进程逐步执行 build，写 <run>.jsonl 与 <run>.proc.jsonl
    ← server follower 跟读 → SSE run/*、proc/stdout-batch
  ← 插件 RunEventsPort 收流 → domain.run / pipeline 归约
  ← 面板渲染：阶梯状态、实时日志、进度、RAM/FLASH 占用

串口链路（并行、独立于 run）：
面板 SerialPane → GET/POST /api/serial/monitor
  → 内核读串口 → serialcodec 切帧 → /api/serial/monitor[/bytes|/decoded]
  → 前端四视图：行 / 字节 / 终端 / 波形（波形按通道 min/max 归一化）
```

### 7.3 为什么不需要镜像仓

- 市场条目直接指向主仓子目录（安装用 `#path:/packages/dsh-elab-cockpit`），
  npm 也从该子目录发布 —— 两条分发链路都不要求「仓库根就是插件包」。
- 历史上曾用 `git subtree split` 推一个只读镜像仓，用于兼容「按仓库根分发」的旧渠道；
  2026-11-02 确认该渠道未使用后**整套退役**（工作流、脚本与文档引用一并移除）。
- 若未来出现必须按仓库根分发的渠道，再新建镜像仓；在此之前主仓子目录是唯一分发形态。

## 8. 发布与维护 Playbook

### 8.1 代码变更（日常）

1. 只改主仓：业务逻辑 `services/elab/**`，步骤/档位/串口词汇 `cockpit/server.py`，
   面板/工具/进程托管 `packages/dsh-elab-cockpit/**`，芯片知识 `packs/**`。
2. 门禁：`npm test` + host/client `tsc --noEmit` + `npm run build`（cwd = `packages/dsh-elab-cockpit`）；
   `elab.cmd doctor`（内核）。
3. 改 `cockpit/server.py` 后，本仓与用户工作检出**两份都要同步**。

### 8.2 发版

1. **内核发版**：改 `COCKPIT_VERSION` / `services.elab.__version__` / 插件
   `DEFAULT_KERNEL_VERSION` + `CHANGELOG.md`；推 main 等 CI 绿后打 `vX.Y.Z`（插件自动
   下载内核归档依赖它）。
2. **插件发版**：改 `package.json#version` + `CHANGELOG.md`；门禁全绿后推 main，
   再 `npm publish`（cwd = 包目录）。**不发新 tag**，npm 版本就是插件的版本身份。
3. 市场条目**不需要**随每个版本改：版本号、下载量、截图由每日探针从主仓子目录刷新；
   只有分类/简介/名字这类展示信息变化才改 YAML 提 PR。

### 8.3 分发纪律

- 插件只有一份源码 `packages/dsh-elab-cockpit/**`，市场和 npm 都取这一份，不存在第二副本。
- 标签只有 `vX.Y.Z` 一套（内核发版）；不要恢复 `plugin-v*`、subtree split 或镜像推送。

## 9. 边界与门禁

| 门禁 | 位置 | 拦什么 |
|---|---|---|
| 分层守卫 | `packages/dsh-elab-cockpit/test/boundary.test.mjs` | 工具层 import 业务层；domain/app 不纯；适配器互引；组装根回引；相对 import 逃出包根 |
| 插件 CI | `.github/workflows/plugin.yml` | `npm test` / host+client `tsc --noEmit` / `npm run build` / `lib` 同步 |
| 内核测试 | `tests/it_cockpit_server.py` | SSE topic 白名单与服务端实际发出事件集合比对 |
| 包索引漂移 | `elab pkg index --check` | `market/index.json` 与 `packs/**` 不一致 |

补充约定：

- 插件不得 import 内核源码、不得共享文件、不得直接读内核事件 JSONL——只能 `/api/*` + SSE。
- 芯片知识只写 `packs/**`；内核不为某厂商开分支。
- 适配包互不依赖，跨包能力走 `pack.yaml` 协议或市场索引。

## 10. 常见违规与正确做法

| 违规 | 症状 | 正确做法 |
|---|---|---|
| 把闭环行为写进插件 | 换内核/无插件时行为不一致；门禁失败 | 写 `services/elab/**`，插件只发 HTTP |
| 把芯片参数写进内核 | 加新芯片要改内核代码，社区无法扩展 | 写 `packs/**`，内核只读 `pack.yaml` |
| 插件直接读事件文件 | 绕过 ICD，版本一升就崩 | 走 `/api/events` SSE |
| 在工具层写业务字段兼容分支 | 内核旧版本行为被永久固化 | 靠 `capabilities.meta` 判定内核过旧并提示同步 |
| 在别处维护第二份插件副本 | 两份代码漂移，市场/npm 装到的版本不一致 | 只改 `packages/dsh-elab-cockpit/**`，市场与 npm 直接取该目录 |
