# 技术方案：DSH 插件独立上架（D 路线：两仓 + 安装向导）

> **状态**：已实施（插件 0.2.0，待发布） · **日期**：2026-11-01 · **决策**：保持 elab-flow / dsh-elab-cockpit 两仓架构，插件**不内置**内核
>
> 实施范围与验证结果见 [§9 实施记录](#9-实施记录)。
>
> **一句话**：D 路线不改架构，不追求"零外部依赖"；目标是把当前的"硬失败"变成"可引导的依赖"——
> 用户装完插件、首次打开面板，就能看见缺什么、点一下补什么，而不是一句"驾驶舱未就绪"。

## 0. 先明确结论

| 问题 | 答案 |
|---|---|
| 两个项目现在依赖吗？ | **代码解耦**（工具层不 import 内核，只走 loopback HTTP ICD，有 `boundary.test.mjs` 门禁）；**运行强依赖**（内核检出 + 主机 Python + 工程工具链） |
| 单独 npm 包能跑吗？ | **不能**。`package.json#files` 只含 `lib / cordis.patch.yml / icon / locale`，不含任何内核文件（[package.json](../packages/dsh-elab-cockpit/package.json#L57-L62)） |
| D 路线算"独立上架"吗？ | 算"**带前置条件的上架**"：市场里能装、能打开、缺依赖时有完整引导；但不承诺装完即可编译烧录 |
| 真正的零依赖要到哪条路线？ | A（内置内核源码，仍需主机 Python）→ B（平台冻结内核，Python 也省掉） |

## 2. 目标与非目标

### 2.1 目标（D 路线）

1. 首次打开面板 → **四步向导**：环境自检 → 内核来源 → 工具链体检 → 工程接入。
2. 每一步都有明确状态（`ok / warn / fail`）+ 可复制诊断 + 下一步动作。
3. 只读优先：**默认不自动 clone、不自动 pull、不自动 pip install**；所有写操作都要一次显式确认。
4. 与市场形态对齐：包内容不变（无内核资产），README 写清前置条件，首启体验由向导承担。

### 2.2 非目标（明确不在本次范围）

- 不在插件包里塞内核源码/二进制（那是 A / B 路线）。
- 不替用户安装 arm-none-eabi / openocd 等工具链（只检测 + 给官方下载页）。
- 不自动装 Python、不自动 `pip install pyserial`（只提示命令）。
- 不改内核业务代码；**除工具层判据统一外，不动 elab-flow**。

## 3. 方案设计

### 3.1 总体：一个状态机 + 三个只读动作 + 一个写动作

```
           ┌──────────┐   /elab/env 全绿        ┌────────────┐
 打开面板 → │ unbound  │ ─────────────────────→ │ env-ok     │
           └────┬─────┘                        └─────┬──────┘
                │ 用户指定 elabRoot / clone 成功        │ 起内核成功
                ▼                                    ▼
           ┌──────────┐   /elab/host 返回 root     ┌────────────┐
           │ root-set │ ────────────────────────→ │ kernel-ok  │
           └──────────┘                          └─────┬──────┘
                                                       │ 工程列表非空
                                                       ▼
                                                  ┌──────────┐
                                                  │ ready    │
                                                  └──────────┘
  （工具链体检结果只是 warn/ok 标注，不阻断任何状态转移）
```

状态存 client service（与现有 `snap.hostOk / kernelOld` 同一层），**只持久化配置**（`elabRoot` / `pythonPath`），状态本身每次重算——避免"上次的绿勾骗了这次"。

### 3.2 新增 HTTP 面（全部在工具层宿主半，仍走 loopback）

| 端点 | 方法 | 职责 | 是否 spawn 内核 |
|---|---|---|---|
| `/elab/env` | GET | **只读环境探测**：python/git/pyserial/工具链版本 | 否（`execFile` 白名单，5s 超时） |
| `/elab/bootstrap` | POST | `{action:"set-root", dir}` 校验并写配置；`{action:"clone", url, dir, confirm:true}` 浅克隆后写配置 | 否（clone 后由下次 `ensureHost` 启） |

设计要点：

1. **探测不冒充体检**：`/elab/env` 只回答"有没有、什么版本"，**不下**"能不能编译"的结论。真实结论仍由内核 `doctor_deep` 在工程接入后跑（已有能力，见 [server.py](../cockpit/server.py#L67-L68)）。这条是为了守住分层：工具层不得复制内核的芯片/工具链判据。
2. **白名单**：只允许 `python|python3|py`、`git`、`cmake`、`ninja`、`arm-none-eabi-gcc`、`openocd` 六类命令，且只传 `--version`；不拼 shell 字符串（`execFile` 数组参数）。
3. **写动作最小化**：只做"指定路径"和"浅克隆"两件事；`pull` 一律只给可复制命令，不自动执行——避免覆盖用户检出里的本地改动。

代码骨架（宿主半，示意）：

```js
// lib/adapters/env/probe.js —— 只读探测，白名单 + 超时 + 失败不抛
const PROBES = {
  python: ['python', ['--version']],
  git:    ['git', ['--version']],
  cmake:  ['cmake', ['--version']],
  ninja:  ['ninja', ['--version']],
  armGcc: ['arm-none-eabi-gcc', ['--version']],
  openocd:['openocd', ['--version']],
];
// 每项返回 { ok, path?, version?, error? }，单项失败不影响整体
```

```js
// 宿主路由（示意）：GET /elab/env
handler: async (req, res) => {
  const env = await probeEnv();          // 不 spawn 内核
  res.end(JSON.stringify({ ok: true, ...env }));
}
```

### 3.3 判据统一（B1 的修法）

- **唯一真源**：`looksLikeElabRoot()`（`cockpit/server.py` + `services/elab`）。
- 发现路由不再自己判根：`discover-route` 的起点改成"由 `elabRoot` 向下扫 `projects/`"，找不到就返回空候选 + 明确错误码（而非另行定义"根"）。
- 向导里所有"这是不是一个可用内核"的文案都引用同一函数的结果，避免两套判据在 UI 上互相矛盾。

### 3.4 UI 落点

| 位置 | 组件 | 内容 |
|---|---|---|
| 面板空态（`hostOk===false`） | 新增 `BootstrapWizard` | 四步卡片；替换现有单行文案（[client.js#L4352-L4354](../packages/dsh-elab-cockpit/lib/client.js#L4352-L4354)） |
| 设置页 | `SettingsSection` 增加"环境"分段 | 复用 `/elab/env` 结果；显示 python 路径/版本、git、工具链灯 |
| 面板头部 | 版本徽标 | 内核版本 < 期望版本时显示"内核旧"，附"复制同步命令" |
| 首次进入 | 可关闭的引导条 | `bootstrap.dismissedAt` 存配置，避免每次打开都弹 |

向导四步的判定与 CTA：

| 步骤 | 判定 | 通过后 | 失败/警告时的动作 |
|---|---|---|---|
| 1 环境 | `/elab/env` 的 `python.ok` | 自动进入步骤 2 | 给 python 官方下载链接 + 设置页 `pythonPath` 输入框 |
| 2 内核 | 已有 root / `set-root` / `clone` | 自动 `ensureHost` | 三个 CTA：指定路径 / 浅克隆（需确认）/ 打开设置页 |
| 3 工具链 | 六项版本探测 | 标 `ok` 或 `warn` | `warn` 不阻断；给官方安装页 + 说明"仅影响编译/烧录/调试" |
| 4 工程 | `/api/projects` 非空 | 进入闭环主视图 | 引导用「＋适配」（已有能力） |

### 3.5 版本对齐

- 数据来源：`/elab/host` 的 `kernelVersion`（来自内核监听横幅/探活，见 [host-process.js#L196-L205](../packages/dsh-elab-cockpit/lib/adapters/kernel-process/host-process.js#L196-L205)）；内核侧版本常量是 `COCKPIT_VERSION`（[server.py#L98](../cockpit/server.py#L98)）。
- 插件声明 `MIN_KERNEL_VERSION`（本次取 `2.1.0`）；比较用语义版本，仅提示、不阻断。
- 旧内核的处理保持现状（`kernelOld` 提示），向导只把它从"一行小字"提升为"可复制的同步命令"：`git -C <elabRoot> pull --ff-only`。

### 3.6 配置持久化

沿用 `/elab/config` 白名单，新增两个键：

```jsonc
{
  "elabRoot": "C:\\Users\\...\\elab-flow",   // 已有
  "pythonPath": "auto",                       // 已有
  "bootstrap": { "dismissedAt": 0, "lastUrl": "https://github.com/<org>/elab-flow" }
}
```

### 3.7 安全与边界（必须守住）

| 约束 | 做法 |
|---|---|
| 不破坏分层 | 工具层只通过 HTTP ICD 与内核通信；不在工具层写芯片/工具链业务判据 |
| 不静默写盘 | clone/set-root 必须 `confirm:true` 且目标目录为空或已是合法根 |
| 不执行任意命令 | 探测走固定白名单；`git` 只用固定参数（`clone --depth 1`） |
| 不泄露路径给远端 | `/elab/env` 只回本机信息的结构，不发起网络请求 |
| 双入口一致 | 向导状态挂在 `(sessionId)` 同一 service 上，原生右栏与 betterSidebar 共用（沿用现有 SSE/服务实例原则） |

## 7. 与 A / B 路线的接口（预留，不施工）

向导把"内核来源"抽象成一个来源枚举，将来换路线只改一处：

| 来源 | D（现在） | A（内置源码） | B（冻结内核） |
|---|---|---|---|
| `user` | 用户指定 / 克隆 | 仍可用（高级用户） | 仍可用 |
| `bundled` | 不实现（`rootSource` 预留） | 包内 `kernel/` 目录 | 包内 `bin/<plat>/elab-kernel` |
| Python | 主机 PATH | 主机 PATH | 内置运行时，探测跳过步骤 1 |

对应改动点：`resolveRoot()` 增加 `bundled` 分支、`resolvePython()` 增加 `bundled` 分支——都在 [host-app.js](../packages/dsh-elab-cockpit/lib/app/host-app.js#L37-L46) 与 [host-process.js](../packages/dsh-elab-cockpit/lib/adapters/kernel-process/host-process.js#L83-L92) 附近，**ICD 与内核零改动**。

## 8. 风险与已知限制

1. **市场对"外部依赖"的容忍度**：前置条件写在详情页 + 首启向导能显著降低差评，但仍不如 A/B 路线"装完就能看到东西"。
2. **clone 体积**：内核仓含 `docs/` 与 `cockpit/web/dist`，浅克隆仍可能有几十 MB；若成为问题，再评估 A 路线（只带运行必需目录）。
3. **Python 环境碎片化**：Windows 上 `py` 与 `python` 行为不同（Store 别名坑）；探测要把三条候选路径都试一遍并在 UI 显示实际选中的可执行文件。
4. **工具链误报**：版本探测只能证明"存在"，不能证明"能链接出 elf"；向导文案不得使用"环境就绪"这类结论性措辞，统一写"已检测到"。
5. **两套判据的历史包袱**：B1 的修复属于工具层小改，但会动 `discover-route.test.mjs`，需一并回归。

### 9.3 与方案的偏离

| 方案原文 | 实际实现 | 原因 |
|---|---|---|
| `bootstrap.dismissedAt` 存 `/elab/config` | 存 localStorage `elab.bootstrap.dismissedAt` | 该键纯前端展示偏好，不进配置白名单可少一次 IPC；将来若要跨设备同步再迁。 |
| `rootSource` 三值 `user/auto/bundled` | 实现 `user/auto`，`bundled` 仅类型预留 | D 路线无内置内核，无来源可标。 |
